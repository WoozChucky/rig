# Basic v0 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The first part of the Basic module, written in Rig in `modules/Basic/`: printing, characters, numbers to and from text, math, memory, strings, allocators (heap, arena, pool), a string builder, and untyped growable arrays and hash tables. Each part has a `tests/run` program that passes compiled and interpreted, on Windows and Linux, and checks clean.

**Architecture:**
- Rig code over a thin C layer, `modules/Basic/libc.rig`: `c_putchar`, `c_malloc`, `c_realloc` and `c_free`, nothing else. Each is C's function under a Rig name of its own (`#foreign libc "putchar"`, issue #135), so a program that loads Basic keeps C's names for itself.
- One file per part. Each part `#load`s the parts it uses, and `modules/Basic/module.rig` loads them all. A program reaches Basic with `#load "../../modules/Basic/module.rig";` from `tests/run`, until `#import` (#116).
- Numbers are written into a buffer the caller gives, so nothing below the allocators allocates. Allocators are passed explicitly. The collections know only their element's size, and hand out `*void`.

**Tech Stack:** Rig as `docs/rig-spec.md` describes it at milestone 3, plus the foreign rename of issue #135 (Fact 10): no generics, enums, `defer`, `#import`, `Any`, overloading or type aliases. The compiler and the test runner are unchanged unless a bug must be fixed (see Global Constraints).

**Prerequisite:** issue #135 (`#foreign libc "NAME"`), on branch `issue/135-foreign-name`. This plan's tasks start only once #135 has merged into `main` and `main` has been merged into this branch. Task 1's first step checks it.

**Spec:** GitHub issue #134, whose Decisions stand. This plan restates the choices the issue leaves open under **Decisions this plan makes**. `docs/rig-spec.md` is the source of truth for what Rig can do; this work doesn't change it, since Basic is a library. Executors read the issue and this plan.

## Global Constraints

- **Rig code style** follows the spec's examples and `tests/run`:
  - Four-space indent. `name :: (a: T) -> R {` with the brace on the line. `snake_case` for procedures, variables and fields. `Upper_Snake` for structs (`String_Builder`, `Int_Table`). `UPPER_SNAKE` for constants.
  - A byte is written as a one-byte string's element, `"-"[0]`, which folds to a `u8` constant (spec 5.9). Use a number with a comment only for a byte with no printable form (`10 // line feed`, `11 // vertical tab`).
  - Comments are study material. Each file starts with a comment saying what the part is and why it's shaped so. Each procedure has prose above it saying what it does, its edge cases (empty input, out of range, null) and why where it isn't obvious. ## Facts (verified on `main` at 6dd89ea, this branch's base)

1. **Writing to standard output.** There's no conditional compilation, so one `#foreign` declaration must work everywhere. Each candidate was tried as a whole program, compiled and interpreted on both hosts, piped:

   | Declaration | Windows compiled | Windows interpreted | Linux compiled | Linux interpreted | After a `printf` |
   |---|---|---|---|---|---|
   | `write :: (fd: s32, buffer: *void, count: u64) -> s64` | `LNK2019: unresolved external symbol write`: POSIX names come from `oldnames.lib`, which the link line doesn't have (`src/link.cpp:99-105`, spec 10.6) | `'write' isn't in the C library at compile time` | works | works | out of order: write's bytes come first, before printf's buffer is flushed |
   | `_write :: (fd: s32, buffer: *void, count: u32) -> s32` | works | works, as ucrtbase.dll's, a second C runtime (`src/os_windows.cpp:612-627`) | `ld.lld: error: undefined symbol: _write` | `'_write' isn't in the C library at compile time` | out of order, as `write` |
   | `putchar :: (c: s32) -> s32` | works | works | works | works | in order |

   - `fwrite`, `fputs` and `fputc` need a `FILE *` for stdout. It is `__acrt_iob_func(1)` on Windows and a data symbol, `stdout`, in glibc. Rig can't declare a foreign variable, and there's no `#if`, so neither is reachable portably.
   - `putchar` is in C17's `<stdio.h>`. So the interpreter takes it from the compiler's own C library on Windows (`src/interp_c_functions.cpp:9-19`, `200-205`; `src/interp.cpp:323-337`) and from libc by `dlsym` on Linux (`src/os_linux.cpp:510-524`). Its bytes go through the same buffer as `printf`'s, compiled and interpreted.
   - There is likewise no portable way to write to standard error: `stderr` is a `FILE *` too.
2. **No type aliases.** A type name is a built-in type's or a struct's (spec 3.1, `docs/rig-spec.md:313`). `Allocator_Proc :: (mode: s32, size: int) -> *void;` is `expected '{', found ';'`, read as a procedure's signature. A procedure type is written out wherever it's used.
   - It may be a struct field, and a struct value may hold a procedure (spec 3.15, `:545`).
   - It can be called through a struct, a pointer to one, or a constant's field: `a.proc(...)`, `p.proc(...)`, `HEAP_ALLOCATOR.proc(...)`. A constant may hold a struct with a procedure field (spec 4.2, `:625`).
   - All of this was tried compiled and interpreted, on both hosts. A Rig procedure value must never reach C: the interpreter refuses it (spec 10.8).
3. **One top level, no overloading.**
   - Every file's declarations share one set of names (spec 4.6, `:744`).
   - On `main` today, a foreign procedure's name is its C function's (spec 7.6, `:1372`). So `free :: (p: *void) #foreign libc;` and a Rig `free` can't both exist: `'free' is already declared at ...`. Issue #135 lifts that (Fact 10).
   - Every name Basic declares is the program's, so a program that loads Basic can't declare a procedure, struct or constant of the same name.
4. **`#load` going up works.** `tests/run/X.rig` with `#load "../../modules/Basic/module.rig";` loads it, and `module.rig`'s `#load "print.rig";` loads its sibling (spec 2.13, `:281`). This was tried with a scratch tree the same shape, compiled, interpreted and `rig check`ed on both hosts. `bin/run-tests` builds only the `.rig` files directly in `tests/run` (`tests/runner.cpp:35-37`), so `modules/` is never built alone.
5. **What the code needs, tried on both hosts, compiled and interpreted:**
   - `*void` takes no arithmetic and can't be dereferenced (spec 3.5, `:349`). `cast(*u8) p + n` moves by bytes (spec 5.14, `:1013-1017`), and `p - q` of two `*u8` is an `int`. A `*void` converts to any pointer implicitly, back too.
   - `cast(u64) f` and `cast(int) f` truncate toward zero and saturate (spec 3.14, `:480`). `cast,trunc(u64) n` reinterprets a negative `int` (`:496`). `0 - magnitude` on a `u64` wraps.
   - A `float64`'s bits are read with `(cast(*u64) *copy).*` on a local copy, since a parameter has no address (spec 7.2, `:1318`).
   - A `[]u8` or `[]string` parameter's elements may be written (spec 7.2). A local array converts to a view of itself (spec 5.17).
   - Several results mixing kinds work: `-> bool, string, *void` and `-> int, bool`.
   - A constant array of `float64` and one of strings, indexed or gone over at run time, work.
   - An untyped float meeting no type is a `float32` (spec 3.12, `:437`). Tests write `x : float64 = 2.5;` or pass literals straight to a `float64` parameter.
6. **C behaviour that differs.** `realloc(p, 0)`:
   - Windows compiled: frees and returns null.
   - Windows interpreted: returns `p` (the compiler's statically linked C runtime).
   - Linux, both ways: frees and returns null.

   This isn't a Rig bug (the maintainer's ruling). C17 leaves it to each C library, and the interpreter calls the compiler's own C runtime where the compiled program calls the system's. Basic never calls `realloc` with size 0.
7. **What `tests/run` requires** (`tests/runner.cpp:4-27`, `CONTRIBUTING.md:65-69`):
   - `NAME.out` is stdout, byte for byte after `\r\n` becomes `\n` on Windows. `NAME.exit` is the status (0 without one). `NAME.err` is stderr (empty without one). `.gitattributes` keeps them LF.
   - Every program also runs interpreted from the repository's root, held to the same files. `rig check` and `rig check --stdin` must exit 0 and print nothing (`tests/runner.cpp:1023-1070`).
   - Timeouts: 60 s compiled, 300 s interpreted (`tests/runner.cpp:167`, `174`).
8. **Runtime errors in Basic.**
   - A runtime error prints `PATH:LINE:COL: runtime error: MESSAGE` to stderr, after flushing stdout, and exits 101 (spec 8.1, `:1512-1518`).
   - For a check in a loaded file, `PATH` is made from the main file's path. From the root, `tests/run/basic_array_bounds.rig`'s error in `array.rig` is `tests/run/../../modules/Basic/array.rig:L:C`, the same compiled and interpreted. This was tried with a scratch tree.
   - A view's bounds check comes before its data's null check, and `*v[i]` checks both without reading (spec 8.4, `:1565`; 8.5, `:1588-1594`).
9. **Commits** are a short imperative summary, an optional body, and no trailers (`CONTRIBUTING.md:110`).
10. **The foreign rename, issue #135, is a prerequisite**, being implemented on `issue/135-foreign-name`.
    - It gives `#foreign libc "NAME"`: a string after the library is the C function's name, and the declaration's own name is its Rig name. An example is `c_free :: (p: *void) #foreign libc "free";`.
    - Without the string, the C name is the procedure's own, as today.
    - Two foreign procedures may name the same C function. A program's `free :: (p: *void) #foreign libc;` and Basic's `c_free` share one symbol, and each call goes through its own declaration's signature.
    - The C name is used for linking and by the interpreter's lookup. The Rig name is used for everything in Rig: calls, values and diagnostics.
    - An empty name is `a foreign procedure's C name can't be empty`. A name with white space is `'fr ee' can't be a C function's name: it has white space`.
    - The spec's section 7.6 describes it once #135 merges. Until then, none of this plan's code compiles on `main`.
11. **Release notes** are grouped by `.github/release.yml`: a pull request goes under the first category one of its labels names, and under "Other" when none does. Its categories are Language, Compiler, Tooling and editor, Documentation, Dependencies and Other. A `library` label exists on GitHub, but no category names it yet.

## Decisions this plan makes

The issue's Decisions stand. These settle what it leaves open.

1. **Output through C's `putchar`** (Fact 1), declared as `c_putchar`: the one call that writes a byte, portable everywhere and in order with C's `printf`. `print_string` loops over the bytes. It is the "one call that writes bytes to standard output" of the issue.
2. **The C layer is `libc.rig`,** each C function under a `c_` name through #135's rename (Fact 10), with exact C types:
   - `c_putchar :: (c: s32) -> s32 #foreign libc "putchar";`
   - `c_malloc :: (size: u64) -> *void #foreign libc "malloc";`
   - `c_realloc :: (memory: *void, size: u64) -> *void #foreign libc "realloc";`
   - `c_free :: (memory: *void) #foreign libc "free";`

   Nothing else in Basic calls C. A program that loads Basic keeps C's own names: it may declare `putchar`, `malloc` and `realloc` itself, and Tasks 1 and 6 test that. `free` is the exception: it is Basic's allocator helper (Decision 3), so such a program declares C's `free` under another name (`c_free` is taken too), as in `libc_free :: (p: *void) #foreign libc "free";`. The README says so.
3. **The allocator helpers are Jai's names:** `alloc`, `resize`, `free` and `free_all`. They're free to take, since Basic's C `free` is `c_free`. The issue's Decisions name them so, and this is the maintainer's ruling.
   - Their parameters are in Jai's order: the memory first, the allocator last, as in `free(memory, allocator)`.
   - #135's sketch, `free :: (a: Allocator, p: *void)`, only illustrates the rename.
4. **Names without overloading:**
   - `find_byte`, `find_byte_from_end`, `find_string`, `find_string_from_end`.
   - `trim`, `trim_left`, `trim_right`.
   - `builder_reset`, `builder_free`, `arena_reset`.
   - `append_string`, `append_byte`, `append_int`, `append_float`, `append_bool`.
   - `table_*` for string keys and `int_table_*` for int keys, on two struct types, `Table` and `Int_Table`.
   - `min_int`, `min_u64`, `min_float32`, `min_float64`, and the same for `max`, `abs` (not `u64`) and `clamp`. Other integer types widen to `int` implicitly (spec 3.13), so `int` and `u64` cover them.
5. **Numbers are written into the caller's buffer.**
   - `format_int(buffer, value, base) -> string` and `format_float(buffer, value, decimals) -> string` return a view of the bytes they wrote at the buffer's start.
   - `INT_TEXT_MAX :: 65;` (64 binary digits and a sign) and `FLOAT_TEXT_MAX :: 320;` (a sign, 309 digits, a point and 9 decimals) are always enough.
   - A smaller buffer stops at the language's bounds check.
   - `print_*` and `append_*` use a local array of that size.
6. **The float method and its limits** (Task 2 has the algorithm):
   - Decimals are clamped to 0..9, and ties round away from zero on the binary value.
   - Below 1e18 the digits are exact for the double given.
   - From 1e18 up, the 17 leading digits are shown and the rest are zeros, approximate.
   - `nan`, `inf` and `-inf` are written as such. A negative value, `-0.0` included, gets `-` (as C's `printf`: `-0.001` with 2 decimals is `-0.00`).
   - `parse_float` is correctly rounded when the significant digits fit in 2^53 and the power of ten is within ±22. Otherwise it is within a few units in the last place.
7. **Bounds are the language's own.**
   - `check_index(index, count)` in `array.rig` indexes a `[]u8` whose count is `count` and whose data is any non-null address. It takes the element's address with `*bounds[index]`, so nothing is read.
   - A bad index stops with the runtime's own `index I is out of bounds (count C)`, at that line of `array.rig`, on stderr, with status 101, the same compiled and interpreted.
   - There's no portable stderr (Fact 1) for a message of Basic's own.
   - Its test's `.err` pins that line and column, so editing `array.rig` above `check_index` means updating `tests/run/basic_array_bounds.err`. The test's comment says so.
8. **Read-only procedures take a collection by value** (`array_get(a, i)`, `table_find(t, key)`), as the issue writes them. Procedures that change it take a pointer.
9. **Allocation edges, decided once in the helpers,** so allocator procedures only ever see `size > 0` and non-null memory to free:
   - `alloc` with a size of 0 or less returns null without calling the allocator.
   - `free(null, a)` does nothing.
   - `resize(null, ...)` is `alloc`.
   - `resize` to 0 or less is `free` and returns null, so no allocator, and so not the heap's `c_realloc`, is ever asked to resize to 0. A comment there says why: what `realloc(p, 0)` does is left to each C library, and the compiled program's and the interpreter's differ (Fact 6).
   - An allocator that can't give memory returns null. The collections don't test for it in v0: a write through the null stops with the language's `null pointer dereference`.
10. **Out of scope:** UTF-8 awareness (all string and char procedures are on bytes, ASCII for `char.rig`), `u64` printing, thread safety, and memory zeroing by allocators (only `array_add(…, null)` and new table entries are zeroed).

## The maintainer's rulings

1. **C's `free` against the helper `free`:** Rig gets Jai's foreign rename first (#135, Fact 10). Basic's C layer uses `c_` names (Decision 2), and the helpers keep Jai's names (Decision 3).
2. **Release notes:** the PR's category label is `library`, which exists on GitHub. Task 1 adds a "Library" category to `.github/release.yml`, after Language.
3. **`realloc(p, 0)`:** not a bug (Fact 6). Basic never calls it with size 0, and says why where `resize` handles size 0 (Decision 9).

## Review Focus

1. **Zero values:**
   - A zeroed `string` (count 0, data null) through every string procedure.
   - A table found in before its first set, whose capacity is 0.
   - A builder turned into a string with nothing in it.

   Tasks 5, 7 and 9 test each. Nothing may do arithmetic that reads through null.
2. **Sizes that aren't multiples of 8:** an array of a 3-byte struct, a table whose values are `bool`s. Entries and elements must stay where the size says, and table values aligned to 8. Tasks 8 and 9.
3. **The extremes:**
   - `int`'s most negative value through `format_int`, `parse_int`, `min_int` and `abs_int`;
   - `-0.0`, infinities and NaN through `format_float`, `min_float64` and `abs_float64`.

   Tasks 2 and 3.
4. **Allocator edges:**
   - `alloc(0)`, `free(null)`, `resize(null)`, `resize` to 0;
   - the heap's `free_all`;
   - pool exhaustion and requests bigger than a slot, which return null rather than fail;
   - an arena allocation bigger than its block size.

   Task 6.
5. **Probing:**
   - a key found past a removed one in the same chain;
   - a removed key's slot taken again;
   - the empty-string key;
   - a key that is a prefix of another (`"app"`, `"apple"`).

   Task 9.

    - accepts an optional `+` or `-`, then one digit or more of the base, either case, and nothing else: no spaces, prefixes or `_`;
    - gives `0, false` for anything else, for a value outside `int`, and for a base outside 2..36.
  - `format_float :: (buffer: []u8, value: float64, decimals: int) -> string`.
  - `parse_float :: (s: string) -> float64, bool`:
    - accepts `[+-] digits [. digits] [(e|E) [+-] digits]`, with a digit at least before or after the point (`5.` and `.5` are numbers), and nothing else;
    - gives `0, false` otherwise;
    - a value too large is an infinity, and `true`.
- Produces, in `print.rig`: `print_int :: (value: int)` (base 10) and `print_float :: (value: float64, decimals: int)`.

**Algorithms:**
- **`format_int`:**
  - Work on the magnitude as a `u64`: `cast,trunc(u64) value`, negated with `0 - m` when `value < 0`, so the most negative `int` needs no special case.
  - Write the digits from the least significant, then put them in order.
- **`parse_int`:** accumulate the magnitude in a `u64`. The limit is 9223372036854775807, plus one when negative. Before each step, `if magnitude > (limit - digit) / base`, it overflows.
- **`format_float`:**
  1. NaN (`value != value`) is `nan`.
  2. The sign: `-` when `value < 0`, or `value == 0 && 1.0 / value < 0`. Then work on the magnitude.
  3. Above `float64`'s largest finite value, it is `inf`.
  4. Clamp `decimals` to 0..9, and `scale` is 10^decimals as a `u64`.
  5. If the magnitude is below 1e18:
     - `whole := cast(u64) magnitude`;
     - `fraction := magnitude - cast(float64) whole`, which is exact;
     - `scaled := cast(u64) (fraction * cast(float64) scale + 0.5)`;
     - if `scaled >= scale`, carry one into `whole` and take `scale` from `scaled`.
  6. Otherwise:
     - divide by 10 until the magnitude is below 1e18, counting the divisions as `zeros`;
     - `whole := cast(u64) (magnitude + 0.5)`;
     - the digits of `whole` come first, then `zeros` zeros, and the decimals are zeros.
  7. Write `whole`, then, when `decimals > 0`, `.` and `scaled` padded with zeros to `decimals` digits.
- **`parse_float`:**
  - Keep at most 19 significant digits in a `u64` mantissa. Leading zeros aren't significant. An integer digit past them raises the decimal exponent by one; a fraction digit past them is dropped. Each kept fraction digit lowers the exponent by one.
  - Read the exponent with its digits capped at 100000.
  - `value := cast(float64) mantissa`. If `mantissa <= 9007199254740992` and the exponent is within -22..22, multiply or divide once by an exact power from a constant `float64.[1e0, ..., 1e22]`. That is correctly rounded.
  - Otherwise multiply or divide by 1e22 while the exponent is beyond ±22 and the value is neither 0 nor infinite, then by the remaining power.
  - Apply the sign last.


**Rules:**
- **The helpers** follow Decision 9 and call `allocator.proc(MODE, ..., allocator.data)`.
  - `resize` passes `RESIZE` with `old_size` and `old_memory`. `free_all` passes `FREE_ALL`.
  - `resize`'s branch for a size of 0 or less frees and returns null. Its comment says why: an allocator is never asked to resize to 0, because what C's `realloc(p, 0)` does is left to each C library, and the compiled program's and the interpreter's differ (Fact 6).
- **The heap:**
  - `ALLOCATE` is `c_malloc`, `RESIZE` is `c_realloc`, and `FREE` is `c_free`.
  - `FREE_ALL` does nothing and returns null: the heap doesn't know what it gave. The comment says so.
- **The arena:**
  - `block_size <= 0` means 4096.
  - Every allocation starts at a multiple of 8 bytes into its block's memory, after the 16-byte header.
  - When the current block can't hold `size` past the aligned `used`, it gets a new block of `max(block_size, size)` bytes. The parent gives `size_of(Arena_Block)` more, for the header. The new block links to the old one through `previous`, and the old one's leftover space is unused.
  - `RESIZE` allocates anew and copies `min(old_size, size)` bytes. `FREE` does nothing.
  - `FREE_ALL` gives every block back to the parent: `block = null`, `used = 0`.
  - `arena_reset` gives back every block but the current (newest) one and sets `used = 0`, so the arena reuses that block.
  - A parent's null is passed on as null.
- **The pool:**
  - `slot_size` is raised to at least `size_of(Pool_Slot)` and rounded up to a multiple of 8.
  - The first `ALLOCATE` after init, or after `FREE_ALL`, gets `slot_size * slot_count` bytes from the parent. It chains every slot into `free_list` so that slots are handed out in address order.
  - `ALLOCATE` of more than `slot_size`, or with no free slot, returns null.
  - `RESIZE` to at most `slot_size` returns the same memory. Beyond, it returns null and leaves the old memory as it was.
  - `FREE` pushes the slot on the free list.
  - `FREE_ALL` gives the memory back to the parent (`memory = null`, `free_list = null`). The pool can be used again.

    - `table_init :: (table: *Table, value_size: int, allocator: Allocator)`
    - `table_set :: (table: *Table, key: string, value: *void) -> *void`: copies `value_size` bytes from `value` (zero when null). A new key is copied into the table's allocator. Returns the value's address in the table, valid until the table next grows.
    - `table_find :: (table: Table, key: string) -> *void`: the value's address, or null.
    - `table_remove :: (table: *Table, key: string) -> bool`: whether it was there. Gives the key's copy back.
    - `table_entry :: (table: Table, index: int) -> bool, string, *void`: for an index in `0..table.capacity - 1` (`check_index`), whether that entry holds a key, the key and its value.
    - `table_free :: (table: *Table)`: gives back every key and the entries. Count and capacity 0.
  - Int keys: `Int_Table`, with the same fields, and `int_table_init`, `int_table_set`, `int_table_find`, `int_table_remove`, `int_table_entry` (`-> bool, int, *void`) and `int_table_free`, each with `key: int` for `key: string`.
  - `TABLE_EMPTY :: 0;`, `TABLE_USED :: 1;`, `TABLE_REMOVED :: 2;`: an entry's state.
- **Layout:**
  - An entry is a header, then the value at the header's size rounded up to 8.
  - The header is `Table_Entry :: struct { hash: u64; state: int; key: string; }` for strings, and `Int_Table_Entry :: struct { hash: u64; state: int; key: int; }` for ints.
  - `entry_size` is the value's offset plus `value_size` rounded up to 8, so every value is 8-aligned.
  - New entries' memory is zeroed with `set_memory`, so every entry starts as `TABLE_EMPTY`.
- **Probing:**
  - Open addressing, linear: start at `hash & (capacity - 1)` and step by one, wrapping. The capacity is a power of two.
  - An entry holds its key's full hash. A string key is compared only when the hashes are equal, and then by count and `compare_memory`.
  - A find stops at an empty entry and passes removed ones.
- **Removal:** marks the entry removed, a tombstone (`count -= 1`, `removed += 1`), so later keys in its chain are still found. A set of a new key takes the first removed entry its probe passed, if any (`removed -= 1`).
- **Growth:**
  - Before a set looks for its key: if `(count + removed + 1) * 4 > capacity * 3`, rehash.
  - The new capacity is 16 when it was 0. It is doubled when `(count + 1) * 2 > capacity`. Otherwise it stays, and the rehash only clears the tombstones.
  - Rehashing reinserts every used entry by its stored hash, without copying keys again.
- **Finds:** a find, remove or entry on a table of capacity 0 touches no entries (Review Focus 1).
