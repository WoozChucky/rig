# Basic v1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The second part of the Basic module, written in Rig in `modules/Basic/`: C strings, files, paths, more strings (copies and UTF-8), time, random numbers, sorting and searching, and the environment. Each part has a `tests/run/basic_*.rig` program that passes compiled and interpreted, on Windows and Linux, and checks clean.

**Architecture:**
- Rig code over v0's thin C layer, `modules/Basic/libc.rig`, which gains the C17 functions this work needs, each under a `c_` name. Every one of them is in the interpreter's table of the compiler's own C functions on Windows, so a `FILE *` that `c_fopen` gives is one the other calls accept, compiled and interpreted (Fact 2).
- One new file per part (`file.rig`, `path.rig`, `time.rig`, `random.rig`, `sort.rig`, `environment.rig`), and `string.rig` grows. Each part `#load`s the parts it uses; `module.rig` loads them all.
- A Rig `string` goes to C through `to_c_string`, a zero-terminated copy from an allocator, freed after the call.
- One compiler change (Task 6, Fact 4): on Windows a foreign procedure whose C name is one of C's time functions that the Universal C Runtime defines only inline (`timespec_get`) or that `msvcrt.lib` links to a 32-bit version (`time`, `gmtime`, `localtime`, `mktime`, `difftime`, `ctime`) is declared under the UCRT's 64-bit export (`_timespec64_get`, `_time64`, `_gmtime64`, `_localtime64`, `_mktime64`, `_difftime64`, `_ctime64`), so a compiled program gets what a C program and the interpreter get. Without it `timespec_get` doesn't link there.

**Tech Stack:** Rig as `docs/rig-spec.md` describes it today (milestone 4 so far: `#import`, `#run`, the Compiler module): no `#if`, generics, enums, `defer`, `Any`, overloading or type aliases. The compiler changes only in Task 6. The test runner changes only in Task 10 (it sets one environment variable).

**Spec:** GitHub issue #145, whose Decisions stand. `docs/rig-spec.md` is the source of truth for what Rig can do. Basic v0's plan, `docs/superpowers/plans/2026-11-14-basic-v0.md`, is the precedent for style. Executors read the issue and this plan.

2. **Why the interpreter agrees on Windows.** `src/interp_c_functions.cpp:94-160` lists every C17 function of `<stdio.h>`, `<stdlib.h>`, `<string.h>`, `<math.h>`, `<ctype.h>` and `<time.h>`, the compiler's own static copies; the interpreter looks there first (`src/interp.cpp:334-343`). `fopen` and `fgetpos` (`:96-103`), `getenv` and `system` (`:109-110`) and `timespec_get` (`:154`) are there, so the `FILE *` and heap they use are the compiler's own, shared by every call. 3. **C's structures, and how Rig declares them** (a Rig struct has C's layout, spec 3.9 and 3.11):
   - `fpos_t` is `long long` (8 bytes) in UCRT and a 16-byte struct in glibc, `{ __off_t __pos; __mbstate_t __state; }`, whose first 8 bytes are the offset. `C_Fpos :: struct { position: s64; reserved: u64; }` (16 bytes) holds either, with the offset in `position` on both hosts. Tried: a 6-byte file gives 6, a 2.25 GiB file 2415919104, and `fsetpos` with the start's `C_Fpos` goes back to 0, on both hosts both ways.
   - `struct timespec` is `{ time_t tv_sec; long tv_nsec; }`: 8 + 8 bytes in glibc, 8 + 4 + 4 of padding in UCRT (`long` is 32 bits). `C_Timespec :: struct { seconds: s64; nanoseconds: s32; padding: s32; }` (16 bytes) fits both: the nanoseconds are below 10^9, so on glibc's little-endian 64-bit `long` they're the low 4 bytes, and the high 4 are 0. `TIME_UTC` is 1 on both. `timespec_get` returned 1 and the time on both hosts (Windows compiled only with Task 6's fix).
   - `SEEK_SET` is 0 and `SEEK_END` 2 on both.
   - C's `long` differs (32 bits on Windows, 64 on Linux), so no declaration of a function that takes or returns one by value is portable but `fseek`'s offset given as 0: Windows reads the low 32 bits of the register, which are 0 too.

## Decisions this plan makes

The issue's Decisions stand. These settle what it leaves open.

1. **The C layer** (`libc.rig`), with exact C types (Facts 1 and 3):

   ```rig
   C_Fpos :: struct { position: s64; reserved: u64; }
   C_SEEK_SET :: 0;
   C_SEEK_END :: 2;
   c_fopen :: (path: *u8, mode: *u8) -> *void #foreign libc "fopen";
   c_fclose :: (file: *void) -> s32 #foreign libc "fclose";
   c_fread :: (buffer: *void, size: u64, count: u64, file: *void) -> u64 #foreign libc "fread";
   c_fwrite :: (data: *void, size: u64, count: u64, file: *void) -> u64 #foreign libc "fwrite";
   c_fseek :: (file: *void, offset: s64, origin: s32) -> s32 #foreign libc "fseek";
   c_fgetpos :: (file: *void, position: *C_Fpos) -> s32 #foreign libc "fgetpos";
   c_fsetpos :: (file: *void, position: *C_Fpos) -> s32 #foreign libc "fsetpos";
   c_ferror :: (file: *void) -> s32 #foreign libc "ferror";
   c_fflush :: (file: *void) -> s32 #foreign libc "fflush";
   c_remove :: (path: *u8) -> s32 #foreign libc "remove";
   c_getenv :: (name: *u8) -> *u8 #foreign libc "getenv";
   c_system :: (command: *u8) -> s32 #foreign libc "system";
   // Task 7, after Task 6's fix:
   C_Timespec :: struct { seconds: s64; nanoseconds: s32; padding: s32; }
   C_TIME_UTC :: 1;
   c_timespec_get :: (time: *C_Timespec, base: s32) -> s32 #foreign libc "timespec_get";
   ```

   - `c_fseek`'s comment says the offset is C's `long`, 32 bits on Windows, so Basic passes only 0.
   - Not used, and why, in `libc.rig`'s header: `ftell` (C's `long`), `_ftelli64`/`ftello` (one host each; `_ftelli64` fails interpreted), `time` (whole seconds, where `timespec_get` gives nanoseconds; and 32 bits compiled on Windows until Task 6), `clock` (a different clock on each host).
2. **A file's size is `fgetpos` at the end** (Fact 3): save the position, `c_fseek(file, 0, C_SEEK_END)`, `c_fgetpos`, `c_fsetpos` back. 64 bits on both hosts, so no 2 GiB limit.
3. **Paths to C use the heap.** The issue's file signatures take no allocator, so `file.rig` copies a path with `to_c_string(path, HEAP_ALLOCATOR)` and frees it after the call. A path with a zero byte would reach C shorter than it is (a different file), so every procedure that passes a string to C refuses one with a zero byte (`find_byte(s, 0) >= 0`) without calling C: `false`, or -1 for `run_command`.
4. **Directories are not files** (Fact 5). `file_open(path, FILE_READ)` reads one byte after `c_fopen`, and fails (closing it) when `c_ferror` is set; otherwise it goes back to the start with `c_fsetpos`. `file_exists` is "`file_open` for reading succeeds", and `delete_file` calls `c_remove` only when `file_exists`. So on both hosts a directory is neither found, read, nor deleted, and Linux's `remove` never takes an empty directory.
5. **Time is a struct.** No type aliases, so `Time :: struct { nanoseconds: int; }`: nanoseconds since 1970-01-01T00:00:00Z, from 1677-09-21T00:12:43.145224192Z to 2262-04-11T23:47:16.854775807Z. The wall clock comes from `timespec_get`, made to link on Windows by Task 6. `Timer` uses the same clock (C17 has no monotonic one), so a clock set back during a measure gives less, even a negative time; the README says so, and nothing clamps it.
6. **Calendar fields:** `year`, `month` 1-12, `day` 1-31, `hour`, `minute`, `second`, `nanosecond` 0-999999999, `weekday` 0 (Sunday) to 6, as C's `tm_wday`. Always UTC.
7. **Random follows PCG's own code**, so the demo's vectors (Fact 7) pin it:
   - `random_u64` is two `random_u32`, the first the high half.
   - `random_bool` is the low bit of a `random_u32` (`pcg32_boundedrand_r(rng, 2)`, whose threshold is 0).
   - `random_int(r, low, high)`: the bounds are swapped when `high < low`. With `span := cast,trunc(u64) high - cast,trunc(u64) low` (wrapping):
     - `span == 0xFFFFFFFFFFFFFFFF` (all of `int`): `cast,trunc(int) random_u64(r)`;
     - `span == 0xFFFFFFFF`: `low` plus a `random_u32`, added as `u64`s;
     - `span < 0xFFFFFFFF`: `pcg32_boundedrand_r` with `bound := cast,trunc(u32) (span + 1)`: `threshold := (0 - bound) % bound` in `u32`, draw `random_u32` until one is at least `threshold`, and give `low + x % bound`;
     - otherwise the same in 64 bits with `random_u64` and `range := span + 1`.

     It always draws at least once, even for `low == high`. Every addition is done in `u64` and the result taken back with `cast,trunc(int)`, so no step overflows a check.
   - `random_float64`: `cast(float64) (random_u64(r) >> 11) * (1.0 / 9007199254740992.0)`, the top 53 bits, in [0, 1).
   - `random_shuffle(r, data, count, element_size)`: for `i` from `count - 1` down to 1, `j := random_int(r, 0, i)`, swap elements `i` and `j` byte by byte (no memory needed). Nothing is drawn for `count <= 1` or `element_size <= 0`. It is the demo's shuffle.
   - `random_from_time()`: the seed is `time_now()`'s nanoseconds and the stream the address of a local, as `pcg32-demo -r` seeds with the time and an address.
8. **Sort:**
   - A top-down merge sort. Equal elements keep their order: a merge takes from the left run unless `less(right, left)`. The scratch space is `count * element_size` bytes from the allocator, given back before `sort` returns. Small runs may use insertion sort.
   - `count <= 1` or `element_size <= 0` allocates and calls nothing.
   - When the allocator gives null, `sort` falls back to an insertion sort in place by swapping neighbours byte by byte: slower, still stable, never a failure.
   - `less_float64` puts NaN after every number (`a` sorts first when `b` is NaN and `a` isn't, or `a < b`), so sorting floats with NaNs is still a strict weak order.
   - `binary_search` gives the first index whose element isn't below the key (C++'s `lower_bound`), and whether `compare(key, element) == 0` there; past the end it's `count, false`. `compare` takes the key first.
9. **String copies own their memory.** `join`, `replace`, `repeat`, `to_upper_copy`, `to_lower_copy` and `path_join` always return a copy, even when nothing changed, so the caller always frees `result.data` with `free(result.data, allocator)`. An empty result is the zeroed string (count 0, data null) and allocates nothing, as `builder_to_string` does. Each allocates exactly once, the result's size worked out first.
10. **Edge choices for strings:**
    - `count_of(s, "")` is 0, and `replace(s, "", new)` is a copy of `s`: an empty `old` matches nothing to replace. `contains(s, "")` is true, as `find_string` finds `""` at 0.
    - `count_of` and `replace` take matches left to right without overlap: `count_of("aaaa", "aa")` is 2.
    - `repeat` of `n <= 0` is `""`.
11. **UTF-8** follows the Unicode Standard's well-formed sequences (Table 3-7): no overlong forms (`C0`, `C1`, `E0` then below `A0`, `F0` then below `90`), no surrogates (`ED` then above `9F`), nothing above U+10FFFF (`F4` then above `8F`, `F5`-`FF`), and every continuation byte `80`-`BF`. Anything else is `0xFFFD, 1, false`, one byte, so a loop moves on by one. An index outside `0..s.count - 1` is `0, 0, false`, and nothing is read. `utf8_count` counts each invalid byte as one. `utf8_encode` writes U+FFFD (3 bytes) for a negative value, a surrogate or one above U+10FFFF, as Go's `utf8.EncodeRune` does; a buffer shorter than the encoding stops at the bounds check.
12. **Paths** (all views, `/` and `\` both separators):
    - `path_file_name`: after the last separator; all of it without one. `"a/b/"` has the name `""`.
    - `path_directory`: before the last separator, without the run of separators that ends there. When that leaves nothing and the path starts with a separator, it is that first separator (the root). No separator: `""`.
    - `path_extension`: in the file name, from its last `.` that isn't part of the dots it starts with, so `.bashrc` and `..` have none and `b.` has `.`. None is an empty view at the path's end.
    - `path_without_extension`: the path less its extension.
    - `path_join(a, b)`: `a`, then `/` unless `a` or `b` is empty, `a` ends with a separator, or `b` starts with one, then `b`. No other rule: an absolute `b` is still joined.
    - Drive letters and `\\server` aren't special: `"C:\x"`'s directory is `"C:"`.
13. **The environment test's variable.** The runner sets `RIG_BASIC_TEST=set by bin/run-tests` at its start (Task 10, Fact 9), which every program it runs inherits, compiled and interpreted, so the test can print its exact value. The test also checks `PATH`, which both systems define, without printing it. `get_environment` refuses an empty name and one with `=` or a zero byte. The README says Windows' names are case-insensitive and Linux's aren't.
14. **`run_command`** flushes every C stream with `c_fflush(null)` first (Fact 6), then gives `system`'s status as C returns it: on Windows the command's exit code; on Linux a wait status, the exit code times 256 when it exited normally (`exit 3` is 768), and 32512 (127 × 256) when the shell can't find the command.
15. **The constants of the parts:** `FILE_READ :: 0; FILE_WRITE :: 1; FILE_APPEND :: 2;` (modes `"rb"`, `"wb"`, `"ab"`; any other mode is `File.{null}, false`), `TIME_TEXT_MAX :: 20;`, `NANOSECONDS_PER_SECOND :: 1000000000;`, `UTF8_REPLACEMENT :: 0xFFFD;`, `UTF8_MAX_BYTES :: 4;`.

3. `weekday := (days % 7 + 11) % 7`: 1970-01-01 was a Thursday (4), and `days % 7` may be negative.
4. Howard Hinnant's `civil_from_days` (https://howardhinnant.github.io/date_algorithms.html), in `int`, its comment explaining the shifted year starting in March:

   ```text
   z := days + 719468
   era := (z >= 0 ? z : z - 146096) / 146097
   doe := z - era * 146097                                  // [0, 146096]
   yoe := (doe - doe / 1460 + doe / 36524 - doe / 146096) / 365   // [0, 399]
   doy := doe - (365 * yoe + yoe / 4 - yoe / 100)           // [0, 365]
   mp := (5 * doy + 2) / 153                                // [0, 11]
   day := doy - (153 * mp + 2) / 5 + 1                      // [1, 31]
   month := mp < 10 ? mp + 3 : mp - 9                       // [1, 12]
   year := yoe + era * 400 + (month <= 2 ? 1 : 0)
   ```
