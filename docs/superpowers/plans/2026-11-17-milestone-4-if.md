# #if: Conditional Compilation and the OS Constants Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Jai's `#if`: code compiled for one system and not the other, decided while compiling, at the top level and as a statement in a body, with the system named by three predeclared integer constants, `OS`, `OS_WINDOWS` (1) and `OS_LINUX` (2).

**Architecture:**
- **The constants** are `Ast_Const` nodes the checker declares before the program's names, from a table in `checker.cpp` (`PREDECLARED_CONSTANTS`) that the VS Code grammar is generated from too. `OS`'s value is the program's system, `Ast_File.system`, which the loader sets (the host's, unless a test says otherwise).
- **The parser** reads `#if` into an `Ast_If_Directive`, one node per arm of an `else #if` chain. Each branch is an `Ast_Block`: statements in a body, top-level declarations at the top level. The top-level ones a file writes go into `Ast_File.ifs`, their branches unread by everything else.
- **In a body**, the checker decides the chain where the statement is (`decide_if`), checks the taken branch's statements in the current scope (no scope of its own), and records the decision on the chain's first arm. Lowering, `#run`'s walk, `goes_past` and `breaks_out_of` follow the taken branch only.
- **At the top level**, the loader decides: it loads the files outside every `#if` as today, then walks the files in load order, deciding each top-level `#if` with a checker that knows only those files' declarations (`check_decider_new`, `check_decide`). A taken branch's declarations join the tree's lists; its `#load`s and `#import`s are read then; its nested `#if`s are decided in source order. The walk also gives each file its place in load order, which can now differ from the order the files were read in: `Source_File.order` and `Ast_File.order`, which `diag_sort`, `ast_declarations` and a final sort of the tree's lists follow.
- **`rig check --stdin-for`** of a file that only a branch not taken loads says so (`rig: error: 'main.rig' loads 'linux.rig' only in an #if branch not taken`), and the VS Code extension then shows nothing for that file and says why once. A branch of a chain whose condition failed isn't "not taken": the program is checked as any program with errors, so the condition's error is reported.

**Tech Stack:** C-style C++23 built with the pinned clang 23.1.5 (`build.bat`, `build.sh`), no STL; JavaScript (Node) for the VS Code extension and its checks.

**Spec:** GitHub issue #147 (`gh issue view 147`), whose Decisions are settled design, restated below as binding; the decisions this plan makes; and `docs/rig-spec.md`, which Task 8 updates. Executors read all three. Related milestone 4 issues: #149 (`defer`, which must keep a `defer` in a taken branch the enclosing block's) and #157 (Basic v2, which will use `#if` for standard error and the like). Neither is part of this plan.

## The maintainer's decisions (binding: the issue's, restated)

1. **The system.** `OS`, `OS_WINDOWS` and `OS_LINUX` are predeclared, as the built-in type names, `size_of`, `it` and `it_index` are: untyped integer constants, `OS_WINDOWS :: 1`, `OS_LINUX :: 2` (0 names no system), and `OS` the one the program is built for, so `OS == OS_WINDOWS` is a constant `bool` that folds.
   - `OS` is the target's; today the target is the host, so `#run`'s code sees the program's `OS`.
   - A top-level declaration of one of them is refused (`'OS' is predeclared: ...`). A local may hide them.
2. **Syntax.** `#if Expression Block [ "else" ( Block | IfDirective ) ]`, at the top level and as a statement in a body. `else #if` chains: conditions worked out in order until one is `true`; that branch is taken and everything after it, later conditions included, isn't. `else if` after an `#if` is refused at the `if`. Bodies are blocks in braces.
3. **The condition** is a constant `bool`, else one of the two condition messages. A condition with an error takes neither branch and checks neither; at the top level the program then behaves as after a failed `#load`: no name anywhere is unknown, nor `main` missing.
4. **The branch not taken is parsed, not checked.** Its syntax errors are reported; nothing else: its names aren't declared, its types not resolved, its `#run`s not run, its `#load`s and `#import`s not read (a file that isn't there is no error), and nothing of it is lowered.
5. **At the top level** a branch holds what the top level holds, nested `#if`s included. The taken branch's declarations join the one top level, visible everywhere; `main` may be in a branch.
   - **When:** after the files outside any `#if` are loaded, before anything else is checked, in load order and source order within a file. A taken branch's `#load`s and `#import`s are read then, and their files' top-level `#if`s join the queue.
   - **Conditions may use** literals, the predeclared constants, and constants declared outside every top-level `#if`, in any file, with what they need in turn. A name declared in a top-level `#if`'s branch, reached from another top-level condition directly or through constants, is the `'LEVEL' is declared in a top-level #if ...` message. A `#run` reached from a top-level condition is refused at the `#run`. A condition in a body has neither limit.
   - **Load order** is the one the program would have with only its taken branches written. Diagnostics are sorted in it, and top-level `#run`s run in it.
   - **Build programs** are recognised once the top-level `#if`s are decided: a `main` or an `#import "Compiler"` in a branch not taken doesn't count.
6. **In a body** `#if` is a statement and makes no scope: the taken branch's statements are the enclosing block's. Its condition is checked when the body is, and may use local constants and `#run`. It reaches its end when its taken branch does. `break`/`continue` in it need a loop around the `#if`.
7. **Not in a struct** (refused), and not an expression.
8. **Recovery:** an `#if` that starts a line in column 1 is the next top-level declaration, as `#load`, `#import` and `#run` are.
9. **`rig check` and the live check** check the taken branches only, for the host's `OS`. A file a program loads only from a branch not taken: `rig check MAIN --stdin-for FILE` says the not-taken message, status 1, and the extension shows no diagnostics for it and says why once in its output channel.
10. **The grammar** needs no new rule for `#if`; `OS`, `OS_WINDOWS` and `OS_LINUX` are `support.constant.rig`, from a compiler table that `test_grammar.cpp` reads.
11. **Debug information:** an `#if` makes no lexical block; the taken branch's code is at its own lines, and the `#if` line has no code.
12. **Later:** `#if` in structs, as an expression, checking for another system, top-level conditions that run code, `OS` as an enum.

## Decisions this plan makes (where the issue leaves a choice)

1. **Task order:** the constants; parsing; the body form; load order apart from reading order; the checker's decider; the loader's top-level decisions; `--stdin-for` and the extension; the spec. Each leaves both hosts green.
2. **Representation.** One node kind, `AST_IF_DIRECTIVE` / `Ast_If_Directive`, for both forms and every arm of a chain (an `else #if` is the next arm, in `else_part`, as `else if` is). Each branch is an `Ast_Block`: at the top level its `statements` are the branch's declarations in source order (`Ast_Proc`, broken entries included, `Ast_Var`, `Ast_Const`, `Ast_Struct`, `Ast_Load`, `Ast_Run`, `Ast_If_Directive`). The decision is on the chain's first arm: `decided`, `failed`, `taken`. Dump: `(#if COND (block ...) ELSE)`, a chain nesting to the right as `if`'s does.
3. **The other two refusals' words**, which the issue gives only for `OS`: `'OS_WINDOWS' is predeclared: it's Windows, one of the systems OS may be` and `'OS_LINUX' is predeclared: it's Linux, one of the systems OS may be`. Each table entry carries its own explanation.
4. **`Ast_File.system`** (`System`: `SYSTEM_NONE` 0, `SYSTEM_WINDOWS` 1, `SYSTEM_LINUX` 2) holds the program's system; 0 means the host's (`host_system()`). `Load_Options.system` sets it, 0 by default; rig always leaves it 0, and the unit tests use it to check both systems on either host. A tree from `parse()` has 0, and a test may set it.
5. **The predeclared constants are `Ast_Const` nodes** each checker makes in its arena, `pos` `{0, 0, 0}`, `type` `&type_untyped_int`, `is_constant`, `constant` the number, `resolve` `RESOLVE_DONE`, and `value` an `Ast_Int` of the same number, checked (so `#run`'s walk, which pushes a constant's value, needs no change).
6. **Which names count as "declared in a top-level #if"** for the condition rule: those in any branch, taken or not, decided or not, at any depth, of the top-level `#if`s read so far, and every declaration of a file that only a taken branch's `#load` brought in (it joins the top level through the branch). The base a condition may use is exactly the declarations of the files read before the first decision, outside every `#if`. A name in a file not read yet is `unknown identifier` (unless a load or a condition has failed).
7. **The decider is a checker with `deciding` set**, made lazily at the first top-level `#if` (programs with none pay nothing), knowing the base names and the constants, saying no "already declared" or built-in-name errors (`check()` says them once, later). `check()` then runs as today on the whole tree, with a checker of its own; what the decider worked out (a constant's value, a struct's layout and `Type`) is kept on the nodes and found done. `check()` makes a struct's `Type` only if it has none yet.
8. **In deciding mode** every `#run` reached is refused, one whose operand is a constant included (`#if #run true`). A call's callee signature may be resolved on the way (the call then isn't constant anyway).
9. **Load order with branches** is computed by one walk after the files outside every `#if` are read: files in load order, each file's top-level `#load`s, `#import`s and `#if`s in source order, a taken branch's in its place, nested `#if`s decided as met. Each file's place in that walk is its `order`. A file's *name* (the path of the `#load` that first reached it) and the place of a `cannot read` error stay those of the reading order: a file reached both from a branch and from outside every `#if`, by two spellings, keeps the first spelling read. (The maintainer has confirmed this.)
10. **Recovery details:**
    - Inside a top-level branch the recovery skips as at the top level, but stops at the `}` that closes the branch (a `}` at brace depth 0 counted from the failed declaration's start), so the branch closes there.
    - Branch contents may be unindented (a C habit from `#ifdef`): no column-1 rule ends a branch. A branch ends only at its `}`; at the end of the file it's `expected '}'` there, unless an error was reported at that very position already (a body never closed inside it), and the whole `#if` is given up as a broken entry with no name.
    - An `#if` in column 1 is among `declares_in_column_1`'s declarations (read again at the top level after a body never closed) and `skip_to_next_declaration` resumes at it inside braces too, as at `name :: (` in column 1. It doesn't by itself end a body (`starts_declaration`): unindented, it's a legal statement there.
    - An `#if` starting a line outside every brace is a resume point, as `#load` and `#run` are (`starts_if`). After a signature, an `#if` is "where the `{` should be" (`expected '{', found directive`), as `#run` is; `parameters_follow` and `variable_follows` treat it as `#run`.
    - In a struct an `#if` in column 1 ends the fields, as a column-1 `#run` does; any other gives the struct up with `#if can't be among a struct's fields, for now`.
    - Top-level branches count as blocks for MAX_DEPTH (`blocks are nested too deeply (more than 1000 levels)`).
11. **A failed top-level condition** sets `Ast_File.lost_a_file`, the existing flag for "the program lacks something": the same silence, no new flag. A misplaced `#load` inside a branch not taken still sets the file's `lost_a_file` (the parser's flag is per file); the program has that syntax error anyway.
12. **`check()` and undecided top-level `#if`s:** a tree from `parse()` keeps its top-level `#if`s undecided, and `check()` leaves their branches out, as if not taken. Only `load_program` decides them; the unit tests of the top-level form go through it (`load_program` takes the main file's text, so no file need exist).
13. **`--stdin-for` and branches not taken:** the loader resolves the `#load`s and `#import`s of every branch not taken (the branches of a decided chain other than the taken one, and at any depth inside such a branch) without reading them or saying anything, and compares each with the `--stdin-for` file by identity. Only when the program doesn't reach the file but such a load names it is the not-taken message said. A file only a file in a branch not taken loads (two steps away) gets `doesn't load`, as the unread file's loads are unknown.
    - **A failed chain's branches are not "not taken"** (the maintainer's change to this decision): a load in any branch of a chain whose condition failed, at any depth inside it, is *undecided*. When the program doesn't reach the file but an undecided load names it, rig doesn't say `doesn't load` or the not-taken message: it goes on and checks the program as for any program with errors, so the condition's error is reported (in another file than the `--stdin-for` one, which the extension shows as its count of the other files' errors), exit 1, and the editor doesn't silently show nothing. Undecided wins over not taken when loads of both kinds name the file.
14. **The extension:** a new output channel named `Rig`. On the not-taken answer, the document's diagnostics are set to none, `main` is remembered as its program, and the channel gets one line, once per document until it's closed: `FILE isn't checked: MAIN loads it only in an #if branch not taken on this system.` (paths as the extension has them).
