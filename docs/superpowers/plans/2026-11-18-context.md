# The Context Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Jai's context. Every Rig procedure but a `#c_call` one is given a `*Context` it isn't given in the source, and `context` names that context: its allocator and its temporary storage. `push_context` runs a block with another. `main` and a `#run` run with Preload's `default_context`, which `__runtime_init` sets up. A `#c_call` procedure, which C calls with none, has no context until it pushes one, as in Jai. Preload gains the temporary allocator, and Basic's allocator parameters default to `context.allocator`. This PR closes #84 as well.

**Architecture:**
- **The lexer** gains two keywords, `context` and `push_context`. **The parser** reads `context` as a primary expression (`AST_CONTEXT`) and `push_context Expression Block` as a statement (`Ast_Push_Context`). At the top level it refuses `push_context`, as it refuses `defer`.
- **The checker** finds Preload's `Context`, `default_context` and `__runtime_init` as it finds `Type_Info` and `Any`, and keeps them on the tree (`Ast_File`). `context` is a place of type `Context` in code that runs (a body, a `#run`'s operand) and in a default value. `push_context` takes a `Context`. A `#c_call` procedure's body outside a `push_context` has none: there `context`, a call of a procedure that takes the context, and a call that leaves out a default value needing one are errors. A program without Preload (a unit test's single file) has no context at all.
- **Lowering** keeps the current context's address in a slot of the procedure (`Lowering.context`). A procedure that takes the context stores its hidden parameter there. `main` and each `#run`'s procedure call `__runtime_init` first, then store `*default_context` there; a `#c_call` procedure has no slot until a `push_context` makes one. Every call of a procedure that takes the context loads the slot and passes it after the hidden result pointers. `push_context` stores the block's context in a slot of its own while the block is lowered. A defer's copy runs with the context where the defer is written. The interpreter runs the same IR.
- **The LLVM backend** describes the hidden parameter as an artificial parameter `context`, the other slots as artificial locals named `context`, and every procedure type that isn't `#c_call` with its `*Context`. `__runtime_init` has no debug information, so `break main` stops at `main`'s first line with the context set up.
- **Preload** holds `Context`, the temporary storage and its allocator. **Basic** defaults its allocator parameters to `context.allocator` and adds `talloc`, the marks, `reset_temporary_storage`, `sprint` and `tprint`.

**Tech Stack:** C-style C++23, built with the pinned clang 23.1.5 (`build.bat`, `build.sh`), no STL. Rig for Preload and Basic. JavaScript (Node) for the VS Code extension's checks. gdb 17.1 and cdb for the debugger tests.

**Spec:** GitHub issue #156 (`gh issue view 156`). Its Decisions are settled design and are restated below as binding. Also #84 (`gh issue view 84`), which this PR closes. Also this plan's own decisions, and `docs/rig-spec.md`, which Task 9 updates. Executors read all of them.

## The maintainer's decisions (binding: the issue's, restated)

1. **In Preload:** `Context` (`allocator`, `temporary_storage`), `Temporary_Storage`, `Temporary_Storage_Page`, `TEMPORARY_STORAGE_SIZE :: 32768`, `temporary_allocator_proc`, `TEMPORARY_ALLOCATOR :: Allocator.{temporary_allocator_proc, null}`, `default_context : Context`, and `__runtime_init :: () #c_call`, which sets `default_context` up once (a second call does nothing): its allocator the heap, its temporary storage Preload's one storage, whose first `TEMPORARY_STORAGE_SIZE` bytes are a global array of Preload's. Pointers to globals are set there, since a global's value can't hold another global's address (4.3).
2. **`context`** is a keyword: the current context, a place of type `Context`. Its fields may be read and assigned, and `*context` is a `*Context`. Assigning `context.allocator` changes the context that is current, which its pusher and every callee sharing it see. It exists in a body and in a `#run`'s code; in a `#run`'s operand it is the run's own context. Anywhere else it is `'context' is only in a body, where a procedure runs`. A default value may use it: it is evaluated in the caller.
3. **`push_context Expression Block`** is a statement. The expression is a `Context` (`push_context needs a 'Context', not 'Allocator'`). A place gives its address, as converting to `Any` does; anything else is copied into a temporary of the procedure. The block runs with it as `context`. Leaving the block by any way out goes back to the context before it: it is lexical, nothing is undone at run time, and a `defer` registered in the block runs while the block's context is current. At the top level it is `push_context can only be in a body`. Basic's README shows the `old := context.allocator; context.allocator = a; defer context.allocator = old;` idiom too.
4. **The hidden parameter.** Every procedure with a body but a `#c_call` one takes a `*Context`, after the hidden result pointers and before the visible parameters. Every call passes the caller's current context, a call through a procedure value too: a procedure type that isn't `#c_call` is one of a procedure that takes it. Foreign and `#compiler` procedures take none. Allocator procedures are ordinary Rig procedures, so they get it too.
5. **Where a context comes from.** `main` takes none: it calls `__runtime_init`, then (#152's) saves the arguments, and runs its body with `*default_context`; a Rig call of `main` passes none. A `#c_call` procedure has no context until it pushes one, as in Jai (settled by the maintainer, below): it pushes `default_context` itself, or the context its caller gave C as user data. 7.6's promise that "code written now keeps working" goes. The compile-time world has Preload's globals of its own and runs `__runtime_init` when it is made; every `#run` starts with that world's `*default_context`, and they share its temporary storage. `--interpret` runs `main` as compiled.
6. **Temporary storage:** allocations from the storage's first 32 KB, then from pages of the larger of 32 KB and the request with its header, from `overflow_allocator`, each allocation at a multiple of 8. `FREE` does nothing; `RESIZE` grows or shrinks the last allocation in place when it fits, and otherwise allocates anew and copies; `FREE_ALL` is a reset. Basic's `reset_temporary_storage()` gives every page back and starts again; `get_temporary_storage_mark() -> Temporary_Storage_Mark` and `set_temporary_storage_mark(mark)` go back to a mark, giving back the pages made since. `high_water_mark` is the most bytes ever occupied. 11. **The temporary allocator's rules** (Task 5), on the storage `context.temporary_storage` (the proc's `data` is unused; the issue's Decision 4):
    - The current region is the newest page (its bytes after the 24-byte header, `size` of them, starting at `start` in the storage's count) or, with no page, the first block (`data`, `size`, starting at 0). Its offset is `occupied - start` (0 for the first block).
    - `ALLOCATE`: the offset rounded up to a multiple of 8. When the region's rest holds `size` bytes (compared as `size <= region size - offset`, so no sum wraps), the memory is there and `occupied` is `start + offset + size`. Otherwise a new page is asked of `overflow_allocator` (its procedure, mode `ALLOCATE`): the larger of `TEMPORARY_STORAGE_SIZE` and `24 + size` bytes; `previous` the newest page, `size` the bytes after the header, `start` the current region's end (its `start` plus its size) rounded up to a multiple of 8, so a page's offsets are as aligned as the count's even after a region whose size isn't a multiple of 8; the gap counts as occupied. Null from it is null, the storage unchanged. A `size` past `int`'s largest less 24 is null too. Then `occupied` is the page's `start + size`.
    - `RESIZE`: when `old_memory` is the last allocation (`old_memory + old_size` is the region's base plus the offset) and the region holds `size` bytes from it, `occupied` moves to `old_memory`'s end at `size` and `old_memory` is returned, larger or smaller. Otherwise `ALLOCATE`'s memory, the first `min(old_size, size)` bytes copied there (`__memmove`), or null with nothing changed.
    - `FREE` does nothing. `FREE_ALL`: each page given back to `overflow_allocator` (`FREE`), newest first; `overflow_pages` null; `occupied` 0. Each returns null.
    - After every `ALLOCATE` and `RESIZE`, `high_water_mark` is the larger of itself and `occupied`. A reset leaves it.
    - So the tail of a region a new page replaced counts as occupied: `high_water_mark` is an upper bound of the first block that would have held everything.
