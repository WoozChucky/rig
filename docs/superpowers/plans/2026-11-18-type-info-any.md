# Type Info and Any Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Jai's runtime type information, trimmed to Rig's types. `type_info(T)` gives a `*Type_Info` describing `T`, laid out as Preload's structs. `Any` pairs a value's address with its type's description, and every value converts to it implicitly. Both work compiled and in `#run`.

**Architecture:**
- **Preload** declares the structs, the tags and `Any`. Their layout is mirrored by constants in `types.h`, as a view's is (`VIEW_COUNT_OFFSET`), and a unit test holds the two together.
- **The parser** reads `type_info(T)` as it reads `size_of(T)`: an `Ast_Type_Info` whose argument is a type.
- **The checker** finds Preload's `Type_Info` and `Any` by name at the top level, in a module's file. `type_info(T)` is a `*Type_Info`, not a constant. `check_convert` converts any value to `Any` and records on the value whether the `Any` takes its address (a place) or a copy's (`Ast.to_any`). Constants and globals refuse what they can't hold. The `#run` walk reaches every type a description reaches, so each struct is laid out first.
- **Lowering** writes each description once per module, the first time something needs it: a read-only global `type_info.N`, with relocations to the descriptions, names and arrays it points at. A worklist fills them, so cycles and long chains need no recursion. A conversion to `Any` builds a 16-byte temporary: the description's address, then the value's (a place's own, or a temporary copy's).
- **The interpreter and the LLVM backend** need nothing new. Both already make read-only globals with relocations to any global, a later one too. The compile-time world's on-demand lowering makes its own descriptions, once per type, in the interpreter's memory.

**Tech Stack:** C-style C++23 built with the pinned clang 23.1.5 (`build.bat`, `build.sh`), no STL; Rig for Preload; JavaScript (Node) for the VS Code extension's checks.

**Spec:** GitHub issue #153 (`gh issue view 153`), whose Decisions are settled design, restated below as binding; the decisions this plan makes; and `docs/rig-spec.md`, which Task 7 updates. Executors read all three. Issues #154 (`print` with `..Any`), #155 (default parameter values) and #156 (the context) build on this; Decision 12 says what they reuse.

## The maintainer's decisions (binding: the issue's, restated)

1. **`type_info(T)`** gives a `*Type_Info` describing `T`. Predeclared, not a keyword: the name followed by `(`. Its argument is a type. `type_info(void)` describes what a `*void` points at. It is no constant (an address); a constant can't hold one; a global's value may be one, the linker writing its address.
2. **One description per type.** Types the same by 3.1's identity share one, so `a.type == type_info(int)` compares addresses. `int` and `s64` have two, with the same contents. `float` is `float32`.
3. **The structs, tags and `Any`** as the issue declares them, in Preload. Floats, `bool`, `string` and `void` have a plain `Type_Info`. `size` and `alignment` are 3.11's (`void`'s 0 and 1). A view and an array share `Type_Info_Array`: `array_kind` says which, `count` is `N` or -1. A struct's `name` is its declared name, its `members` its fields in order with their offsets. A procedure type's `is_variadic` marks a `..T` last parameter, described as `[]T`. Self-referring structs point back at their own description.
4. **Converting to `Any`** wherever a value goes into something of a known type (3.13): a declaration with a type, an assignment, an argument (`..Any` included), a return, a field or element of a literal. A place gives its own address; anything else is copied into a temporary of the procedure, which lives until the end of the statement holding the conversion. A value of type `Any` converts as itself. An untyped constant takes its default type first; `null` is a `*void`; a literal without its type is refused. What isn't a value keeps its message. Only to `Any` itself. Nothing converts from `Any` implicitly. A constant can't hold a converted `Any`, nor can a global's initial value, for now.
5. **Where descriptions live:** the program's read-only data, one per type, only for the types the program uses (those `type_info` names and those of values converted to `Any`), with every description reachable from them. Names are string literals there; the views of members and of parameter types see read-only arrays.
6. **At compile time** the interpreter makes them in its own memory, laid out the same, on demand, once per type. A `#run`'s result holding a `*Type_Info` or an `Any` can't be baked.
7. **Debug information:** nothing new.
8. **Later:** enums' and unions' descriptions, notes, names for every type, `Any` from a constant without a copy, baking from `#run`.

## Decisions this plan makes (where the issue leaves a choice)

"Decision N" alone is one of these; the maintainer's are "the issue's Decision N".

1. **Task order:** Preload's declarations; parsing and checking `type_info`; describing types (lowering); checking the conversion; lowering it; compile time; the spec. Each leaves both hosts green. Until Task 3 no test lowers a `type_info`; until Task 5 none lowers a conversion; until Task 6 no `#run` describes a type whose structs it hasn't laid out.
2. **Finding Preload's names.** `declare_top_level` records, for a top-level struct declared in a module's file (`Source_File.in_module`), named `Any`, its `Type` in `Checker.any_type`, and named `Type_Info`, its `Type` in `Checker.type_info_type`. A program can't declare either (Preload has them), so these are Preload's. Without Preload (a unit test's single file, or `Load_Options.no_preload`), `type_info` is `'type_info' needs Preload's 'Type_Info', which the program doesn't have`, and `Any` is an unknown type.
3. **The layout is C++ constants** in `types.h` (below), as a view's is, and lowering writes descriptions from them. A unit test loads the real Preload and checks every struct's size, alignment and field offsets, and every tag's value, against them.
4. **Descriptions in the IR.** Each is a read-only global (`has_layout`, `is_read_only`, `rig_type` null) named `type_info.N`, N counted per module in the order they're made, with the size and alignment of its kind's struct. A struct's member array is `type_info.N.members`, a procedure's arrays `type_info.N.parameters` and `type_info.N.results`, each read-only, aligned to 8, made only when not empty (an empty view is zeros). Each name, the struct's and each member's, is a `str.N` of its own (`add_bytes`). `type_info(T)` lowers to `addr @type_info.N`.
5. **Made once, filled by a worklist.** `type_info_global(l, t)` returns the cached index (`Lowering.type_infos`, by `pointer_key` of `t`), or makes the global empty, caches it, and queues it. The queue is drained in order, first in, first out, by the outermost call only. Filling one reads the indexes of the descriptions it points at through `type_info_global` (made and queued if new), never recursing in C++: a chain of structs, each pointing at the next, has no limit. The bytes are written last, through the global's index (the globals array may move). So `Node`'s `next` member points at `*Node`'s description, which points back at `Node`'s.
6. **Constants and globals.** `type_info_address(e)` (`checker.h`, beside `literal_address`) finds the `type_info(T)` a value is, through casts between pointer types and fields or elements of constant data, as `procedure_address` does. A global may hold one, alone or in a literal or a view's array, a cast of such a literal or a field of one included (`check_global_value`; `constant_data` and `is_known` take it as a known value); `lower_global` gives it a global of bytes, and `constant_bytes` a relocation. A constant holding one, or a value converted to `Any`, is 4.2's `a constant's pointer can only be null or a string literal's address`, at the value: the issue's "(its pointers, 4.2)". A global's value converted to `Any` is `a global's value must be known while compiling, for now`, checked before `is_constant`. A literal with a value converted to `Any` is no constant data (`constant_data`, `is_known`).
7. **The conversion is recorded on the value.** `check_convert`, meeting `Checker.any_type` from any other type: a literal without its type is `check_default_type`'s message; `null` becomes a `*void`; an untyped constant takes its default type (`check_default_type`); then `e->to_any` is `ANY_PLACE` when `expr_is_place(e)`, else `ANY_COPY`. The value keeps its own type. Lowering, the constant checks and the `#run` walk read the mark.
8. **`cast(Any) e` is the conversion** (3.14's first row: a cast to a type the value converts to implicitly is that conversion), for a value of any type, a pointer and a procedure value included (Fact 6: `check_cast` would send those to its pointer and procedure cases, which refuse a struct). `check_cast` doesn't mark it constant; `lower_cast` lowers its value through `lower_value` to `Any`.
9. **Several results don't convert to `Any`.** `a, b = f();` with an `Any` target keeps `check_multi_assign`'s `a value of type 'int' doesn't convert to 'Any' implicitly`, at the target. **Settled by the maintainer:** a unit test pins it; a follow-up issue may add the conversion.
10. **The temporaries.** An `Any` is a 16-byte slot of the caller's frame, one per conversion in the source, filled where the value is worked out: the value's address first (a place's, through `lower_address`, its checks included; or a copy's: a slot of the value's type, then the value worked out and put there), then the `Any`'s slot, then the description's address at offset 0 and the value's at 8. An argument is then copied as any aggregate argument is. Each slot is reused when the same conversion runs again; the spec promises it only to the end of the statement.
11. **The `#run` walk** reaches each `type_info(T)`'s `T` and each converted value's type for its description (`reach_described`), with a table of its own (a type walked for its layout still needs walking for its description). Describing a type lays out every struct it reaches and makes its late fields, behind pointers, in views and procedure types too. So describing `*S` while `S` is being laid out (a `#run` in one of `S`'s counts) is `'S' is defined in terms of itself`, at `S`, as reaching `S` by value is.
12. **What the later issues reuse.** `lower_value_address(l, e, place)`, the address of a value, a place's own or a temporary copy's, is #156's rule for `push_context` ("as converting to `Any` does"). `..Any` (#154) needs nothing more: each gathered argument converts as any argument does. A default value (#155) converting to `Any` is checked and lowered at the call by the same path. The descriptions list no hidden context parameter (#156 adds it to calls, not to types).
13. **Editor:** the template's `size-of` rule takes both names, `\\b(size_of|type_info)\\s*(\\()`, its comment saying so; the grammar is regenerated. `Any` and the structs are struct names, coloured as any other.
14. **Test names:** `tests/run/type_info`, `tests/run/any`, `tests/run/type_info_while_compiling` (with `.build.out`); `tests/errors/type_info_misuse`, `tests/errors/any_conversions`, `tests/errors/run_type_info`.
