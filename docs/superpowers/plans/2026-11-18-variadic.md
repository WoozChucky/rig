# Variadic Rig Procedures Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Jai's `..T`: a Rig procedure's last parameter, `name: ..T`, gathers a call's remaining arguments into a view, `[]T`, of a temporary array of the caller's; `..e` spreads an existing view or array into it whole; procedure types say `..T` and calls through values gather and spread as direct calls do. C's bare `..` stays a foreign procedure's.

**Architecture:**
- **The parser** reads `name: ..T` as a parameter marked variadic (`Ast_Param.is_variadic`, its `type_expr` T), `..T` as a procedure type's last parameter (`Ast_Type.is_variadic`), and `..e` as a prefix operator, an `Ast_Spread`, wherever a unary operand starts. C's bare `..` keeps its rules; `Ast_Proc.is_variadic` becomes `is_c_variadic` so the two can't be confused.
- **The checker** gives a `..T` parameter the type `[]T` (T resolved as a view's element), marks the procedure's type (`Type.is_variadic`, part of its identity and its name), and refuses the parameter on foreign, `#c_call` and `#compiler` procedures and in `#c_call` types. A call checks its fixed arguments as always, then either converts each other argument to T and records the temporary's type, `[N]T` (`Ast_Call.gathered`), or accepts one spread of exactly `[]T` or `[N]T` as the call's last argument. A spread anywhere else is refused.
- **Lowering** passes the `..T` parameter as any `[]T` aggregate argument (spec 10.4): gathered, a `[N]T` temporary built element by element, as an array literal is, and a view of it in a temporary of its own (zeroed when N is 0); spread, the operand lowered as a `[]T` argument (an array seen as a view, spec 5.17) and copied as any aggregate argument is, its elements never. The interpreter runs the same IR, so `#run` needs nothing more.

**Tech Stack:** C-style C++23 built with the pinned clang 23.1.5 (`build.bat`, `build.sh`), no STL; JavaScript (Node) for the VS Code extension's checks.

**Spec:** GitHub issue #150 (`gh issue view 150`), whose Decisions are settled design, restated below as binding; the decisions this plan makes; and `docs/rig-spec.md`, which Task 5 updates. Executors read all three.

## The maintainer's decisions (binding: the issue's, restated)

1. **The parameter.** `name: ..T` is the last parameter of a procedure with a body, after any number of others, none included. In the body it is a `[]T` parameter, read-only as every parameter (7.2). Anywhere but last: `'..' must be the last parameter`.
2. **Where it can't be:** a foreign procedure (`a foreign procedure can't take '..int': C's other arguments are written '..' alone, as in (format: *u8, ..)`), a `#c_call` procedure (`a #c_call procedure can't take '..int'`: C passes no view, 7.6), a `#compiler` procedure (`a #compiler procedure can't take '..int', for now`). C's bare `..` on a procedure with a body keeps its error, its hint naming the new form: `only a foreign procedure can take C's '..'; a Rig procedure takes more arguments as '..T', as in (values: ..int)`.
3. **Calls, one by one.** At least one argument per parameter before the `..T` one (`'sum' takes at least 1 argument, but 0 were given`), and any number more. Each extra argument converts implicitly to T as an argument to a T parameter does (`argument 3 of 'sum' has type 'string', which can't be converted to 'int'`); an untyped constant takes T. All arguments are evaluated left to right (5.18) into a temporary `[N]T` of the caller's, and the parameter is a view of it. With none, the view is zeroed: count 0, data null.
4. **Calls, spread.** `..e` as the call's last argument, `e` a `[]T` or a `[N]T`, passes `e` as the view (an array converts as 5.17 says: a place's own elements, a constant's read-only data, a temporary copy otherwise). Nothing is copied: the callee sees the caller's elements.
   - Exactly `[]T` or `[N]T`, elements not converted: `'..' spreads a '[]int' into 'rest', which needs a '[]Any'`.
   - All the variadic arguments, never mixed with single ones: `'sum' takes its '..' arguments one by one or as one spread view, not both`.
   - Anywhere else (no `..T` parameter, a foreign procedure's C `..`, an argument not last, an expression outside a call): `only the arguments of a '..' parameter can be spread, as in f(..values)`.
   - Forwarding is spreading: `log :: (format: string, args: ..Any) { print(format, ..args); }`.
5. **Lifetime.** The temporary array lives until the end of the statement holding the call. A callee keeping the view past its return holds a dangling view: a memory error no check catches (8.6), as for any view of a temporary (5.17).
6. **Procedure types and values.** A variadic Rig procedure is a value, and its type says `..T`: `(first: int, rest: ..int) -> int` has type `(int, ..int) -> int`, which is not `(int, []int) -> int` (3.15's identity gains the mark), and messages write it so. A call through such a value gathers and spreads as a direct call does. `#c_call` procedure types can't have it. `a procedure type can't take '..'` stays for C's bare `..` only.
7. **Calling convention.** The view is an aggregate argument, passed as 10.4 passes any: a pointer to the caller's copy of the 16-byte view. A debugger sees the parameter as a `[]T` (10.7).
8. **`#run`, the interpreter:** nothing special; the same IR.
9. **Later:** named arguments; default values before a `..T` parameter (#155: refused for now when they come, `a procedure with a '..' parameter can't have default values, for now`); `..Any` (#153) and `print` (#154) build on this.

## Decisions this plan makes (where the issue leaves a choice)

"Decision N" alone, here and in the tasks, is one of these; the maintainer's are "the issue's Decision N".

1. **Task order:** parsing (with the refusal of every spread, so nothing new reaches a stage that can't take it); types and signatures; checking calls; lowering with the run tests; the spec. Each leaves both hosts green. Until Task 2 a `..T` parameter is checked as a `T`, and until Task 3 every spread is refused; until Task 4 no test lowers a variadic call.
2. **Representation:**
   - `Ast_Param.is_variadic` and `Ast_Param.dots` (the `..`'s position); its `type_expr` is T, and the checker gives it the type `[]T`.
   - `Ast_Type.is_variadic` and `Ast_Type.dots` on an `AST_TYPE_PROC` whose last parameter is written `..T`; `params`' last is T.
   - `AST_SPREAD`, `Ast_Spread { Ast *operand; }`, at its `..`; its type is the operand's once a call accepts it, null otherwise.
   - C's `..` is renamed: `Ast_Proc.is_c_variadic`, `Ast_Proc.c_dots_pos` (was `is_variadic`, `variadic_pos`), so no code mistakes one kind for the other. `Ir_Proc.is_variadic` keeps its name: only C's reaches the IR.
   - `Type.is_variadic` (`TYPE_PROC`: its last parameter is a `..T`, `params[param_count - 1]` the `[]T`); `type_proc_of` gains `bool is_variadic`, after `is_c_call`.
   - `Ast_Call.gathered`: the `[N]T` of a call's one-by-one `..` arguments, N from 0; null when the callee takes no `..T` or the call spreads.
   - `call_variadic_type(Ast_Call *)` (`checker.h`, `check_expr.cpp`): the callee's `..T` parameter's `[]T`, directly or through a value, or null.
   - Dumps: a parameter `(rest (.. int))`, a procedure type's `(params int (.. int))`, a spread `(spread (name more))`.
3. **A spread is a prefix operator** at the unary level, as `-` is (`Unary = ( "-" | "~" | "!" | "*" | ".." | "#run" ) Unary`): `..a + b` is `(..a) + b`, whose spread isn't an argument, so it's refused; `x := ..xs;` parses and is refused by the checker with the issue's message, not `expected an expression`. A spread is a level as the other prefix operators are (`open_level`, `set_height`). `procedure_follows` keeps `'(' '..'` as a parameter list (a constant's value can't be a spread anyway), its comment saying so.
4. **T is resolved as a view's element** (`resolve_element(c, T, true)`, behind a pointer), so `rest: ..S` needs S's layout no earlier than `rest: []S` does, and `..void` is `'void' is only a pointer's target, as in *void`, at T. Nothing else is said about T: a `..[]int` or a `..(int) -> int` is fine.
5. **Counting with a spread:** the spread stands for all the `..` arguments, so the arguments before it must be exactly the fixed ones: fewer is the "at least" message counting only those (`sum(..ints)` is `'sum' takes at least 1 argument, but 0 were given`), more is the mix message. A refused spread counts as an argument of its own position, with no type, so nothing more is said about it (`sum(..ints, 1)` gives one message, the spread's).
6. **Positions and names:** the signature refusals at the parameter's `..`; the spread messages at the spread's `..`; a conversion at the argument's start; too few at the callee's start, as now. Through a procedure value, whose type keeps no parameter names, the spread message names the parameter by its type written `..T`: `'..' spreads a '[2]u8' into '..int', which needs a '[]int'`.
7. **Messages the issue doesn't give**, which the new `..T` would make false or misleading:
   - the parser's bare `..` in a procedure type: `a procedure type can't take '..': a procedure that takes C's '..' can't be a value` (the issue's prefix kept);
   - `'printf' can't be a value: it takes C's '..', which no procedure type can say`;

8. **The gathered temporary's type** is made by `check_array_type(c, T, N, at)`, `at` the first `..` argument's start: it lays out a struct T (the run needs its size), and N times a large T past `TYPE_MAX_SIZE` is `'[3]Big' is too big` there, not a crash in `type_array_of`. 9. **A spread's operand is checked with `check_operand`:** it has its own type, never one from the parameter, so `.. .[1, 2]` is `this literal's type isn't known; write it before the '.', as in int.[1, 2]`.
10. **A Rig procedure with C's bare `..`** (refused, Decision 2) keeps saying nothing about its calls' extra arguments; a spread in such a call is refused, as for C's `..`.
11. **Lowering's shapes:** fixed arguments first, as now. Gathered: `emit_slot([N]T)`, then each argument in order, its element's address (`emit_field_address`, `i * T.size`) and its value (`lower_value(arg, T)`) put there (`emit_put`), exactly as `lower_literal` builds an array; then `emit_view([]T, N, temporary)`, passed as it is: it is the caller's fresh copy, so no second copy. N = 0: `emit_slot([]T)` and `emit_zero`. Spread: `lower_value(operand, []T)` and the aggregate argument's usual copy into a slot of its own (16 bytes; the elements never). C's extra arguments keep `extra_argument_type`.
12. **Lifetime as built:** the temporary is a slot of the caller's frame, reused when the same place runs again; the spec promises it until the end of the statement holding the call (issue's Decision 5), no longer.
13. **Editor:** no grammar change (Fact 11): the `..` of a `..T` parameter and of a spread keep the range operator's scope, as C's `..` does; `check.js` gains assertions that pin it.
14. **Test names:** `tests/run/variadic` (`.rig`/`.out`); `tests/errors/variadic_rig_signatures`, `tests/errors/variadic_rig_calls`.
