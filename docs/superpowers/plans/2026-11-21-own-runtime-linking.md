# Link Without Visual Studio or libc6-dev: Rig's Own Runtime and Import Libraries: Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `rig build` links every program with `lld-link` or `ld.lld` and Rig's own runtime alone, so a user of `rig` needs nothing installed besides Rig: no Visual Studio on Windows, no `libc6-dev` on Linux (#125).

**Architecture:**
- **Windows:** build.bat compiles a freestanding `runtime/windows.c` (start-up, which gives `main` the wide arguments in UTF-8, `__chkstk`, `_fltused`, `atexit` and its kin, msvcrt.lib's aliases) and `runtime/windows_stdio.c` (the 219 functions of `legacy_stdio_definitions.lib`, over the UCRT's `__stdio_common_*` and `__conio_common_*`) with the pinned clang into `bin\rig_runtime.lib`, and makes `bin\ucrtbase.lib` and `bin\kernel32.lib` from committed `.def` files with the pinned `lld-link /lib`. `link_windows.cpp` loses the Visual Studio Setup Configuration API and the SDK registry lookups: one command line, `lld-link ... /NODEFAULTLIB OBJECTS rig_runtime.lib ucrtbase.lib kernel32.lib`, all three by path beside `rig.exe`. A program imports exactly `ucrtbase.dll` and `kernel32.dll` (Facts 9, 10, 21). Preload's `__save_command_line` loses its Windows branch and declarations: it saves the `argv` it is given, UTF-8 already, on both systems (Q2 (b)).
- **Linux:** build.sh compiles `runtime/linux.c` (`_start` calling glibc's `__libc_start_main`, and `libc_nonshared.a`'s `atexit`, `at_quick_exit`, `pthread_atfork`) into `bin/rig_runtime.o`; `ld.lld` links it and the objects against the system's `libc.so.6` and `libm.so.6` by path, found in five directories (Facts 11-13).
- **Shipping:** the four files join the release archives, their packaging scripts, the installers' requirement messages, the Install page, CI (a `debian:stable-slim` run of the tests), and the spec. The compile-time interpreter is untouched (Fact 19).

**Tech Stack:** C-style C++23 (the compiler, the tests), freestanding C17 with top-level `__asm__` (the runtime), built with the pinned clang 23.1.5 and linked with the pinned lld (`build.bat`, `build.sh`); Windows PowerShell 5.1 (the `.def` generator); POSIX sh and cmd (packaging, installers); GitHub Actions.

**Spec:** issue #125 (`gh issue view 125`), whose Decisions are settled, with the maintainer's answers to this plan's three questions (the last section); `docs/rig-spec.md` 7.6 (`2144`, `2291`), 10.5 (`3190-3206`), 10.6 (`3208-3260`) and 10.8 (`3307`), which the tasks change. ## Not in this plan

- **What links today and won't:** C11's threads (`thrd_*`, `mtx_*`, `cnd_*`, `tss_*`, `call_once`), which import `VCRUNTIME140_THREADS.dll`, not on every machine; `vcruntime.lib`'s `_Atomic_*` helpers; msvcrt.lib's `_freea_s`, `setjmp`'s aliases, `_matherr`, its data aliases (`_tzname`, `_ctype`, `_sys_errlist`, the `*_dll` names), which no Rig declaration can name; `libmvec`. Each is an issue of its own if a program needs it.
- **C libraries built with MSVC** that need its runtime: milestone 6's libraries, which may bring Visual Studio back as an option for them.
- **`scripts/test_install.sh`'s and `test_install.ps1`'s checks of an installed release's runtime files:** they install the latest release, 0.3.0, which has none; an issue for after the next release.
- **A Windows CI job** without Visual Studio (a container): CI stays Linux only (spec 9); Task 3's by-hand check stands in.
- **Cross-linking.**
- **A UTF-8 environment** (`envp`, `_environ`): the start-up leaves the C runtime's narrow environment as a C program has it; Basic reads variables wide already.

## Settled by the maintainer

- **Q1. The memory functions:** (a), imported from `ucrtbase.dll`, which exports them (Fact 2); the runtime defines none (Decision 6).
- **Q2. The arguments:** (b), the Windows start-up converts the wide arguments to UTF-8 and passes those to `main`; Preload drops its Windows branch and declarations (Decisions 6, 12; Fact 21).
- **Q3. msvcrt.lib's other names:** (a), all carried: `atexit`, `at_quick_exit`, `_onexit` and the 20 aliases (Decision 6, Fact 8).
