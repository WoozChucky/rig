# Enums and enum_flags Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Jai's enums in Rig. `Mode :: enum { ALLOCATE; RESIZE; FREE; FREE_ALL; }` and `Flags :: enum_flags u8 { ... }` declare types of their own over an integer type; members are named `Mode.FREE`, or `.FREE` where the type is known; flags combine with `| & ^ ~`; enums cast to and from integers, compare, fold as constants, run in `#run`, cross into C as their integer type, are described by `type_info` and written by name by Basic's `print`, and show by name in the debugger. Preload's and Basic's "constants until enums", and `OS`, become enums.

**Architecture:**
- **Lexer and parser:** `enum_flags` becomes a keyword. `NAME :: enum [T] { ... }` and `NAME :: enum_flags [T] { ... }` are top-level declarations (`Ast_Enum`), each member an `Ast_Const`. A `.` followed by a name, where an expression starts, is a member without its enum (`Ast_Dot_Name`). `Mode.FREE` already parses as a member access.
- **Types:** `TYPE_ENUM`, one `Type` per declaration (made with the top level's names, as a struct's is), carrying its integer type's size, alignment and sign, its integer type, whether it is flags, and its declaration. `TYPE_UNTYPED_MEMBER` is the type of `.NAME` until it meets an enum, as `TYPE_UNTYPED_LITERAL` is `.{...}`'s.
- **Checker:** an enum's member values are worked out where first needed (`resolve_enum`), with earlier members visible as plain constants of the integer type. `.NAME` takes its enum in `check_convert`, the mechanism untyped `.{...}` literals use, plus the two operator cases the issue lists. Enums don't convert implicitly (but the untyped `0` to a flags type); casts to and from integers follow the integer casts' rules.
- **Lowering, the interpreter, `#run`:** an enum is its integer type everywhere below the checker (`type_integer_of`). Members are constants, so they lower as numbers. Baking a `#run` result bakes an enum as its integer, typed as the enum.
- **Type information and Basic:** Preload's tags become `Type_Info_Tag :: enum`, with `ENUM :: 11`, and a new `Type_Info_Enum`; lowering describes an enum's names and values; Basic's `print` writes members by name and flags as `A | B`.
- **Debug information:** a DWARF/CodeView enumeration type of the members, over the integer's base type.
- **Conversions:** Preload's `Allocator_Mode`, `Type_Info_Tag`, `Array_Kind`; Basic's `Table_Entry_State`; `OS`, a constant of the predeclared enum `Operating_System`.

**Tech Stack:** C-style C++23, built with the pinned clang 23.1.5 (`build.bat`, `build.sh`), no STL; LLVM 23.1.5's C API; Rig for Preload and Basic; JavaScript (Node) for the VS Code extension's checks; gdb and cdb for the debugger tests.

## Decisions this plan makes

1. **One PR, five tasks**, each green on both hosts, each a reviewer's gate:
   1. Declare enums and check their uses (lexer, parser, types, checker; no lowering).
   2. Compile and run enums (lowering, backend, interpreter, `#run`, C, the debug type).
   3. Describe and print enums (type information, Preload's tags and array kinds as enums, Basic's `print`).
   4. Switch Preload, Basic and `OS` to enums.
   5. Show enums in gdb and cdb.

   Until Task 2 nothing lowers an enum: Task 1's tests are unit tests and `tests/errors` only, and its spec examples are ```` ```rig fragment ```` or ```` ```rig error ````. Until Task 3, an enum converted to `Any` or named by `type_info` reaches `type_info_tag`'s assert: no Task 1 or 2 test does either (they print `cast(int) e`).
2. **The type.** `TYPE_ENUM`, made in `declare_top_level` with the top level's names (once, kept on `Ast_Enum.declared`, as a struct's), with its integer type's `size`, `align` and `is_signed` set there already (the type after the keyword can only be a built-in type's name, which `type_from_name` gives without resolving anything; any other name gives `int` there, and `resolve_enum` reports it), so a struct declared before its enum is laid out at the enum's size (`enum_run.rig`'s `Holder` before `Level :: enum u16`), `name` the declared name, `underlying` the integer type, `is_flags`, and `enum_decl`. Each declaration is its own type (3.1's identity). The integer type is a name after the keyword (`enum s32`), a built-in integer type (`s8`..`u64`, `int`); none is `int`. Any other type is `an enum's type must be an integer type, not 'float32'` and the enum then takes `int`, so its uses say nothing more. Enums are declared at the top level only, as structs are (a body's is `enums can only be declared at the top level, for now`). An enum with no members is allowed.
3. **Members are `Ast_Const`s** of the integer type, at their names. A member with no value gets, once its number is known, an `Ast_Int` of it as its `value` (as `declare_predeclared` does for `OS`), so every walk that reaches a constant finds a value. `resolve_enum(c, e)` works the values out where first needed (its own turn in `check()`'s pass, `Mode.FREE`, a `.FREE` meeting it, `check_enum_values` from a `#run`'s walk), as `resolve_global` does, with `Ast_Enum.resolve` and `c->resolving`: a value that needs its own enum (through another enum or a `#run`) is `'E' is defined in terms of itself`, at the enum's name, and every member is then unknown. Values:
   - an explicit value: a constant expression that converts to the integer type (`300 doesn't fit in 'u8'` at the value; `the value of constant 'B' isn't known while compiling`);
   - an implicit one in an `enum`: the previous member's plus one, the first 0;
   - an implicit one in an `enum_flags`: the lowest power of two above every earlier member's value, read as unsigned at the type's width, the first 1. So `{ A; B :: 8; C; ALL :: A | B | C; D; }` is 1, 8, 16, 25, 32;
   - one past the type's range is `256 doesn't fit in 'u8'`, at the member's name.
4. **Earlier members inside the body** are in a scope of the enum's own, pushed while its values are checked (no other scope open, as `resolve_global` leaves them): each member joins it after its value is checked, so `LAST :: C + 3` and `ALL :: A | B` use plain integer constants. Outside the body no scope holds them (settled, Q2).
5. **`.NAME`** is an `Ast_Dot_Name` (`pos` the `.`, `name_pos` the name) of type `type_untyped_member` until it meets a type, in `check_convert`, exactly where `.{...}` meets one: a typed declaration, an assignment, an argument (`..T` ones included), a return, a field or element of a literal, a default value, and a cast around it. Meeting an enum, it becomes that member, a constant (`'Mode' has no member 'FRE'` when it has none); meeting anything else, `'.FREE' needs an enum type, not 'int'`; meeting none (`check_default_type`, `check_operand`, `Any`, C's `...`), the issue's message. The issue's two operator cases are added in `check_binary`:
   - the other side of `==` or `!=` from an enum value: the operands are checked with `check_value`, and an untyped member converts to the other side's type;
   - the other operand of `| & ^` from a flags value, and `~` on an untyped member: `.A | .B` and `~.A` stay `type_untyped_member` (as `1 | 2` stays untyped) until they meet a type, when `check_convert` converts their operands and folds them. Met by an enum that isn't flags, their operator's own message at the operator (`'|' needs integers, not 'Mode'`); by a type that is no enum, `'.A' needs an enum type, not 'int'` at the first `.NAME` in them.

   `< <= > >=` don't take `.NAME`: the issue lists `==` and `!=` only. `type_waits_for_one(t)` (`type_untyped_literal` or `type_untyped_member`) replaces each test of `== &type_untyped_literal` that defers or refuses (Fact 4).
6. **`Mode.FREE`**: `check_member` looks its operand up first when it is a name not in parentheses; a name declaring an enum (a local hides it as any top-level name) makes the member access a constant of the enum, `Ast_Member.of_enum` set and `index` the member's. 7. **Conversions.** Nothing converts to or from an enum implicitly but an untyped integer constant whose value is 0 to a flags type (so `1 - 1` too). `cast(T) e` between an enum and any integer type is the integer cast between their integer types: a constant must fit (`300 doesn't fit in 'Small'`), any other value is checked at run time as 8.3 says (`runtime error: the value doesn't fit in 'Small'`), `cast,trunc` takes enums as it takes integers; whether a member has the value is never checked.
