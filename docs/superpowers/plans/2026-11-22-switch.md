# The switch, #complete and #through Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Jai's switch in Rig. `if x == { case 1; a(); case 2; b(); #through; case; c(); }` runs the case whose constant value equals `x`, worked out once, with no fallthrough unless a case ends with `#through;`, `case;` the default anywhere. It switches on integers, enums, `bool`, `string` and pointers; `if #complete m == { ... }` makes an enum switch name every member's value, and a `#complete` switch without `case;` that meets a value no member has stops the program with `runtime error: no case for value 7 of 'Mode'`. It works compiled, interpreted and in a `#run`, and a debugger steps into the case that runs.

**Architecture:**
- **Lexer and parser:** `case` becomes a keyword; `#complete` and `#through` are directives. `==` directly followed by `{` ends every expression (a `{` starts no expression, so it can never be a comparison); `parse_if` then reads a switch, an `Ast_Switch` of `Ast_Case`s, each case's statements an `Ast_Block` of their own. `#through;` is read only as a case's last statement.
- **Checker:** the switched expression is checked once and must be an integer, an enum, a `bool`, a string or a pointer; each case's value converts to its type through `check_convert` (so `.FREE` takes the enum) and must be a constant; duplicates are found by value (strings by bytes); `#complete` compares the enum's members' values with the cases'. Spec 6.11's rule gains the switch (`goes_past`, `breaks_out_of`).
- **IR, lowering, interpreter, backend:** a new terminator, `IR_SWITCH`, for integers, enums, bools and pointers (LLVM's `switch`); strings lower to a chain of `==` comparisons. A case is a scoped block (its defers run when it's left); `#through` jumps into the next case's block. A `#complete` switch without `case;` sends any other value to a block calling a new helper, `__rig_no_case`, which writes the message with the value in decimal and panics, as `__rig_bounds_failed` does.
- **Debug information:** the dispatch is at the `if`, each case a lexical block at its `case`, the jump out of a case at the switch's `}`, a `#through`'s jump at the `#through`.

**Tech Stack:** C-style C++23, built with the pinned clang 23.1.5 (`build.bat`, `build.sh`), no STL; LLVM 23.1.5's C API; JavaScript (Node) for the VS Code extension's checks; gdb and cdb for the debugger tests.

**Spec:** GitHub issue #222 (`gh issue view 222`), whose Decisions are settled design; section 2 of the milestone's design, `docs/superpowers/specs/2026-11-22-milestone-5-type-system-design.md`, whose scope, non-goals, anti-goals and constraints bind every task (section 4, tagged unions, #224, builds on this switch); and `docs/rig-spec.md`, which each task updates for what it builds. Executors read all three and this plan.

## Decisions this plan makes

1. **One PR, three tasks**, each green on both hosts, each a reviewer's gate:
   1. Parse and check the switch (lexer, parser, AST, checker, editor; no lowering).
   2. Compile and run the switch (IR, lowering, interpreter, backend, `#run`, the runtime error).
   3. Step through a switch in gdb and cdb (debug positions checked, spec 10.7).

   Until Task 2 nothing lowers a switch: Task 1's tests are unit tests and `tests/errors` only, and its spec examples are ```` ```rig fragment ```` or ```` ```rig error ```` (rig check never lowers).
2. **Telling a switch from an `if`.** In `parse_expression`'s loop, an `==` whose next token is `{` is no operator: the loop stops before it, at every level, so the whole expression ends there. A `{` starts no expression, so this never takes a comparison away from any program: `== {` was always an error. Then `parse_if` reads `== {` as a switch on everything before it. So `if a == b {`, `if (a == b) {` and `if x == .{1, 2} {` are ifs as today; `if (x) == {` switches on `x`; `if a && b == {` and `if it > limit == {` switch on `a && b` and `it > limit` (the `==` that ends the expression is never inside it); `if (x == {` is `expected ')', found '=='`. Anywhere else an expression is followed by `== {` (`#if`, `while`, `for`, `push_context`, `x := a == {`) it is what was expected there, found `'=='`. The grammar stays unambiguous: A.4 says that `"==" "{"` ends an `Expression`, and A.3's `IfStmt` has a second form.
3. **Words.** `case` is a keyword (`TOKEN_CASE`, after `TOKEN_PUSH_CONTEXT` in `lexer.h`, `tokens.cpp`'s names and `KEYWORDS`), `KEYWORDS_CONTROL` in the editor. `#complete` and `#through` are directives (spec 2.7's list becomes eleven).
4. **The tree.**
   - `Ast_Switch` (`AST_SWITCH`), at the `if`: the switched expression; the `==`'s position; whether it's `#complete` and where that is; its cases in order, the default among them; its `}`. The checker fills in `default_case`, `checks_no_case` (a value no case has is a runtime error: `#complete` without `case;`; #224 will set it for a tagged union too) and `covers_every_value` (`#complete`, every member's value has a case, no errors), and `failed` (the switched expression had an error).
   - `Ast_Case` (`AST_CASE`), at its `case`: its value (null for `case;`), its statements as an `Ast_Block` at the `case` whose `end` is the switch's `}` (where the jump out of the case is, Decision 17), and the position of a `#through` ending it (line 0 when none). The `#through` is not a statement in the block.
   - The switch is a statement of its own. `else if x == {` is allowed: an `if` is what follows `else`, and a switch is one; the parser makes the switch the one statement of an `Ast_Block` at the `if`, ending at the switch's `}`, which becomes the `else_part`, so every walker of else-if chains (`check_if`, `breaks_out_of`, `goes_past`, `lower_if`, `ast_dump`) stays as it is. A switch takes no `else` of its own: its default is `case;` (`a switch takes no else; ...`).
5. **Reading the body.** After `== {`, the cases: `case` [expression] `;`, then statements up to the next `case` or the `}`. The statements are read by the loop `parse_block_rest` has, made a helper both use, which in a switch also stops at `case` and at `#through` (so recovery, column-1 declarations and misplaced `#load`s behave as in any block). `#through ;` is taken only there, as the case's last statement: anything but `case` or `}` after it is `#through must be its case's last statement`; `}` after it is `#through can't end the last case: ...`. A `#through` anywhere else, and a `case` anywhere a statement starts outside a switch's braces, are refused in `parse_statement` (messages above). The switch's braces are one block level (`MAX_DEPTH`), counted at its `{` as `parse_block` counts; each case's block is inside that level, as an if's block is.
6. **What it switches on.** The switched expression is checked once (`check_operand`, so `.FREE` and `.{...}` alone are reported); an untyped constant takes its default type (`if 3 == {` is an `int`, an untyped float a `float32`, then refused). It must be an integer, an enum (flags included), `bool`, `string`, or a pointer (any `*T`, `*void` included): anything else, a procedure value, `Any` and the resizable arrays included, is `a switch needs ... not 'T'`, and the cases' values are then checked against nothing but their own types. A switch on a constant is an ordinary statement: every case is checked and compiled, and the one that matches runs (an `#if` is what picks code while compiling).
7. **The cases' values.** Each converts to the switched type as an assignment's value does (`check_value`, then `check_convert`, `report_no_conversion`), and must be a constant:
   - an integer, enum or `bool` case: `is_constant` (a literal, a constant, a member, `.NAME`, a flags expression of members, a cast, a `#run`'s number);
   - a string case: constant data (`constant_data` finds a string literal, or a `#run`'s string, whose bytes the checker compares);
   - a pointer case: `null`, the one pointer value that is `is_constant`. A string literal's address (`P :: cast(*u8) "x";`) is constant data but has no number until the program is linked, so two of them can't be compared while compiling, and LLVM's `switch` can't take one: `a pointer's case can only be null, as in case null;` (settled, Q1).

   Anything else is `a case's value must be known while compiling`. A case's value is never evaluated at run time.
8. **Duplicates.** Each case's value is compared with every earlier case's, once both checked cleanly: the converted constants' 64 bits (`Ast.constant`) for scalars, so `case 1;` and `case ONE;`, and two members sharing a value, are the same; the bytes for strings, so `case NAME;` and `case "rig";` are. The second is `this value already has a case at PATH:L:C`. A second `case;` is `this switch already has a 'case;' at PATH:L:C`. `case;` may be anywhere.
9. **`#complete`.**
   - On a switched expression that isn't an enum: `#complete needs an enum, not 'int'`, and the switch is checked as one without it. `enum_flags` types are enums: each member's value needs a case.
   - Otherwise, once `check_enum_values` gave the values and every case's value checked cleanly (a case with an error would make a second message about the member it meant), each member's value, in declaration order, must equal some case's value, `case;` or not. Each value missing is named once, by the first member that has it, `'Mode.FREE_ALL'`, and all are listed in one message at the `#complete`: one is `'A' has no case`, two `'A' and 'B' have no case`, more `'A', 'B' and 'C' have no case`.
   - `covers_every_value` is set when nothing is missing; `checks_no_case` when there's no `case;`.
10. **`#through`** goes on into the next case's statements, in source order, without comparing its value; into the `case;` too when that comes next. The case is a block that's left there: its defers run first (spec 6.12).
11. **Scopes.** Each case's statements are a block and a scope of their own (`check_scoped_block`), so two cases may declare the same local name. The switch adds no loop: a `break` or `continue` in a case acts on the loop around the switch (`check_jump` needs nothing new), leaving the case's block (its defers run, `lower_jump`), and with no loop around is `'break' is only allowed inside a loop`.
12. **Reaching the end (spec 6.11).** A switch goes past when its switched expression checked (`!failed`) and either it may find no case (it has no `case;` and doesn't cover every value: a `bool` switch with both values and no `case;` included, since only `case;` and `#complete` count) or some case that doesn't end with `#through` reaches the end of its block. A case ending with `#through` goes on into the next one, which is judged in its turn. A `#complete` switch that reported a missing member, and one whose switched expression had an error, are taken not to go past, so their message is the only one. `breaks_out_of` looks into every case's block.
13. **Lowering, the dispatch.** At the `if`, in the scope around, the switched expression is lowered once (`lower_value`), then:
    - an integer, an enum, a `bool` or a pointer: one `IR_SWITCH` on the value (a pointer through `IR_PTRTOINT` to an `i64`, `null` its 0), each case's value (its constant's bits, zero-extended from the type's width, as `IR_CONST`'s) to its case's block, and every other value to the default case's block, or the no-case block when `checks_no_case`, or `after`;
    - a string: its count and data loaded once, then, case by case in source order, the comparison `==` makes (`lower_string_comparison`'s code, factored so the switch passes the four values and the position: the null check at the switch's `==`, then `__rig_string_equal`), branching to the case's block or to the next comparison; after the last, where an integer switch's default goes.
14. **Lowering, the cases.** Each case's block is lowered with `lower_scoped_block` (a scope at its `case`, its defers run at its end). Then a case that gets to its end jumps, at the switch's `}`, to `after`, or, ending with `#through`, at the `#through`, to the next case's block. `after` exists when some case gets there, or some value finds no case and there's neither a default nor a no-case block; otherwise the IR block has ended, as after an `if` that always returns.
15. **No case at run time.** `IR_SWITCH`'s default for a `checks_no_case` switch is a block at the `if` that calls a new helper, `__rig_no_case(ptr buffer, ptr where, i64 where_length, i64 value, i1 value_is_signed, ptr tail, i64 tail_length)`, then `unreachable`. It writes `WHERE "no case for value " V TAIL` into the buffer, V in decimal as `append_number` writes it, TAIL the switch's own ` of 'Mode'\n` (a global, `add_bytes`), and panics with `c` = `where_length`, so the interpreter's message is `no case for value 7 of 'Mode'`. The buffer is a local of the fail block, `where_length + tail_length + 38` bytes (`no case for value ` is 18, a number at most 20), so the helper's size doesn't depend on any one program: it's made the first time a switch needs it, its body after every body as `__rig_string_equal`'s is; on demand, third, at index 2, body and all (`ir_lowering_new`'s assertion gains it). The value is widened to an `i64` by the enum's integer type's sign. Neither `--no-bounds-checks` nor `#no_abc` removes the check: it's not a bounds check, and the issue asks for it as the null check is.
16. **`IR_SWITCH`.** A terminator, `switch T %a, bD [V: bN, V: bM]`: `a` the value (an integer type or `i1`), `target` the default block, and a new field of `Ir_Instr`, `Array<Ir_Case> cases`, each `{u64 value; s32 block;}`, `value` zero-extended from T's width. The interpreter takes the first case whose value equals `v[a]`, or `target`; the backend builds `LLVMBuildSwitch` with `LLVMAddCase`s. It's chosen over a chain of `IR_CMP` and `IR_BRANCH`, which would also work, because the dispatch is then one instruction at the `if` for a debugger, and LLVM's own lowering of a switch (a jump table, a binary search) is what C's switch gets.
17. **Debug positions.** The switched expression and the dispatch are at the `if`, in the scope around the switch (a string switch's comparisons too). Each case is a lexical block at its `case`. The jump out of a case is at the switch's `}`, as an if block's is at its own `}` (spec 10.7): stepping from a case's last statement stops at the `}`, then the code after, never at another case's line. A `#through`'s jump is at the `#through`; its target is usually laid out right after it, so it may have no instruction (Fact 11). The no-case call is at the `if`.
18. **`#run`.** The walk (`check_run.cpp`) pushes a switch's cases' blocks, its string cases' values (constant data that lowering writes) and its switched expression, in the order that makes the switched expression walked first. Lowering on demand and the interpreter need nothing else.
19. **Spec placement.** The switch is a new section 6.14, after 6.13 push_context, so no section is renumbered (the spec, the code's comments and the tests cite section numbers throughout); 6.5 says that `if x == {` is a switch and points there.
