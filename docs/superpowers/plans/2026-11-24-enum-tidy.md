# Tidy what enums left: plan

**Goal:** Do what issue #233 asks: tidying left by enums (#221) and the switch (#222). One item changes performance; nothing changes what a program means.

**Spec:** issue #233 (`gh issue view 233`), and `docs/rig-spec.md` 3.18 and 6.14, which stay as they are.

## Tasks (one PR, one task)

1. **Look up enum members in a table.**
   - **Code:** `enum_member_index` (`src/checker.cpp:961`) scans the members one by one. Instead, give each enum a `Table` from a member's name to its index, built the first time the enum is looked up, in the checker's arena, using the repo's own `Table` as `check_switch` does.
   - **Behaviour:** messages and their order stay the same. A member is visible only from its declaration on inside its own body: the "earlier members" rule of spec 3.18, and `find_enum_member`'s innermost-declaration rule from #221's review. So the table must not make a later member visible early. Either build it once the enum's values are all known, or keep the body's lookups as they are.
   - **Test:** `tests/unit/test_checker.cpp` gets a test with a generated 20,000-member enum and a `#complete` switch naming every member (`case .M_i;`). The checker must accept it with no messages. Add no timing assertion, but run it and report the time before and after; it should be a few milliseconds, not about a second.
   - **Comments:** fix `a_switch_of_many_cases_checks`, whose comment says naming members would be quadratic.

2. **`print_enum` and `print_item`** (`modules/Basic/print.rig`) share one helper that reads an integer of a given size and sign out of memory. Output must not change. The `basic_print_*` tests and the `.err` files that name `print.rig` lines may need their line numbers updated.

3. **`parse_enum` against `parse_constant`** (`src/parser.cpp`):
   - share them if that's shorter and clearer;
   - otherwise leave a comment in `parse_enum` saying why a member's value isn't parsed by `parse_constant`.

4. **The `OS` constant's integer node** (`src/checker.cpp`) is set up three times. Write a shared helper only if it reads better; otherwise leave a comment.

5. **Long lines:** bring the comment lines added by #221 and #222 back to the column their files keep. This covers trailing field comments and the `Operating_System :: enum {...}` comment line, in `src/`, `modules/` and `tests/`. Don't touch code lines or long lines that existed before #221.

**Done when:** all tests pass on Windows and Linux, in debug and release builds (unit tests, end-to-end tests, and debugger tests under cdb and gdb), the VS Code check passes, and no behaviour changes apart from the lookup's speed.
