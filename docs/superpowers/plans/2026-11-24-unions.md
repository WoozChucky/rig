# C Unions and Anonymous Members Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** C's untagged unions in Rig. `Value :: union { i: s64; f: float64; p: *void; }` lays every member at offset 0, its size the largest member's rounded up to the largest alignment; any member is read or written at any time. Anonymous `union { ... };` and `struct { ... };` members inside a struct or a union, nested to any depth, have their fields reached directly (`e.key`). `Value.{f = 1.5}` gives one member by name, the other bytes zero. Unions are not compared, work compiled, interpreted and in a `#run` (baked as their bytes), as globals and constants, are described by `type_info` (`Type_Info_Struct.is_union`), printed by Basic as `union` and their size, shown by gdb and cdb as union types, and passed to C by pointer.

**Architecture:**
- **Parser and AST:** `union` stops being reserved. `NAME :: union { ... }` is an `Ast_Struct` with `is_union`, read by `parse_struct`. Among a struct's or a union's fields, `union {` or `struct {` starts an anonymous member: an `Ast_Field` with an empty name whose `anonymous` is a nested `Ast_Struct` with no name, ended by `;` after its `}`.
- **Types:** a union is a `TYPE_STRUCT` with `Type.is_union`, so everything a struct value already does (copies, pointers, places, `Any`, arrays and fields of it, circles in layouts, untyped `.{}`) carries over; only layout, literals, constant folding, baking, description, printing and debug information look at the flag. An anonymous member is a field of an anonymous type (its own `TYPE_STRUCT`, no name), made when its outer struct is laid out; nothing is flattened in the `Type`.
- **Checker:** member lookup goes through one function, `type_find_member`, which searches a type's own fields, then its anonymous members' fields, depth by depth, and returns the chain of field indices; `check_member` rewrites `e.key` into the chain of implicit member accesses it means (`e.<anonymous>.key`), so lowering, places, null checks, `#run`'s walk and debug positions need nothing new. `using` (#225) adds its fields to the same search. Names that clash across an anonymous member's braces are refused where declared, as C refuses them.
- **Lowering, `#run`, type information, Basic:** literals record the field each value goes to (`Ast_Literal.fields`); a baked union is its bytes (`Ast_Literal.bytes`); `Type_Info_Struct` gains `is_union: bool` at offset 56 (size 64); `print` writes `union(16 bytes)`.
- **Debug information:** a union is a `DW_TAG_union_type` (`LLVMDIBuilderCreateUnionType`), an anonymous member a member with no name of an anonymous composite type, as clang describes C's; LLVM's CodeView writer turns that into an `LF_UNION` and lists an anonymous member's fields in the outer type.

**Tech Stack:** C-style C++23, built with the pinned clang 23.1.5 (`build.bat`, `build.sh`), no STL; LLVM 23.1.5's C API; Rig for Preload and Basic; JavaScript (Node) for the VS Code extension's checks; gdb and cdb for the debugger tests.

**Spec:** GitHub issue #223 (`gh issue view 223`), whose Decisions are settled design; section 3 of the milestone's design, `docs/superpowers/specs/2026-11-22-milestone-5-type-system-design.md`, whose scope, non-goals, anti-goals and constraints bind every task (section 4, tagged unions, #224, and section 5, `using`, #225, build on this one); and `docs/rig-spec.md`, which each task updates for what it builds. ## Decisions this plan makes

1. **One PR, four tasks**, each green on both hosts, each a reviewer's gate:
   1. Declare and check unions and anonymous members (parser, AST, types, checker, the layout checked against clang's; no lowering).
   2. Compile and run them (lowering, constants and globals, `#run`, C by pointer, the debug types).
   3. Describe and print them (`Type_Info_Struct.is_union`, Preload, Basic's `print`).
   4. Show them in gdb and cdb.

   Until Task 2 nothing lowers a union or a struct with an anonymous member: Task 1's tests are unit tests and `tests/errors` only, its spec examples ```` ```rig fragment ```` or ```` ```rig error ````. Until Task 3, `print` of a union writes its members as a struct's, and no test does it.
2. **A union is a struct with a flag.** `Ast_Struct.is_union` and `Type.is_union`; `TYPE_STRUCT` kind. A new kind would have to repeat every place a struct value goes (copies, `Any`, places, pointers, arrays, untyped `.{}`, circles, late fields, the `#run` walk); with the flag, only the places the issue changes look at it. Each declaration is its own type (3.1). `#224`'s tagged union, which has a tag and a switch, is not this type.
3. **Layout** (in `lay_out`, by `s->is_union`): every member at offset 0; the alignment the largest member's (1 with none); the size the largest member's size rounded up to that alignment. So a union with no members, or only members of size 0, has size 0, as an empty struct does; `union { a: [5]u8; b: u32; }` is 8, aligned to 4. A union holding itself by value, directly or through structs, arrays or other unions, is `'U' contains itself; ...` as a struct is; behind a pointer, a view or a resizable array it's allowed. Late fields work as a struct's (a union's pointer member is laid out from what's written).
4. **Anonymous members, syntax.** Among a struct's or a union's fields, `union {` or `struct {` starts one: its fields as `parse_struct` reads them, recursively, its `}`, then `;`, required, as every field ends with its `;` and as the issue writes it (`... union { key: ...; mouse: ...; }; }`). It is an `Ast_Field` with an empty name, at the keyword, `type_expr` null, `anonymous` an `Ast_Struct` with no name and `is_union` by the keyword. A named field of an anonymous type (`x: union { ... };`) is not in the language (`expected a type`, as today). Each anonymous member's braces count a level against `MAX_DEPTH`; past it, the parser's message above. The dump writes one as its struct without a name: `(struct Event (kind s32) (union (key Key_Event) (mouse Mouse_Event)))`, and a union declaration as `(union Value (i s64) (f float64))`.
5. **Anonymous members, types.** Each is a field of an anonymous type, a `TYPE_STRUCT` (with `is_union` by its keyword) made by its outer's `lay_out`, in the outer type's arena (`t->arena`, so the decider's and the checker's are one, Fact 5), kept on the anonymous `Ast_Struct.declared`, its fields laid out there and then (no circle of its own: it's reached only through its outer, whose circle it is in), its `resolve` set as its outer's. Its `Type.name` is empty, so its description and its debug type have none, as C's have none; `type_name` writes it `union` or `struct`, which messages quote. `layout_levels` of an anonymous member is one more than the deepest of its fields'. `resolve_late_fields` goes into anonymous members. Nothing is flattened: the outer `Type` has one field for the member, at its offset, which `Type_Info` and the debugger show (the issue: "members with an empty name").
6. **Lookup.** `type_find_member(t, name, &path)` in `types.cpp`: `t`'s own named fields first, then the fields of its anonymous members, then theirs, depth by depth (breadth first), the first found winning; `path` gets the field indices from `t` down, empty when none has the name. Decision 7 makes the first found the only one, for now; #225 adds `using` fields to the same walk at their depths and reports two at one depth there, at the use. `check_member` and the literals (Decision 9) use it; `type_field_index` stays where a late field's own struct finds it by name, crossing no anonymous member (`make_late_field`, `resolve_late_fields`); lowering stops using it (Decision 9). In `check_member`, a path longer than one makes the operand a chain of `Ast_Member`s the checker builds, one per anonymous member, each with an empty name, its `index`, its type, `pos` the written name's and `start` the operand's, so `p.key` through a `*Event` is `p.<anonymous>.key`: the pointer is followed and checked once, at the name, as for `p.kind`; the chain is a place when `e` is one; `*e.key` is an address; lowering, `#run`'s walk and the debugger positions see ordinary member accesses.
7. **Clashes are refused where declared.** C makes an anonymous member's fields the outer struct's (C11 6.7.2.1p13; clang: `duplicate member 'x'`), so a name reachable twice from one top-level struct or union, at whatever depths, is `'x' is already declared at PATH:L:C`, at the later one in source order. Names in one pair of braces are `lay_out`'s `earlier_field`, as today (anonymous members' empty names clash with nothing: a struct may have several); across braces, the top-level declaration's layout compares every reachable name once, in source order, after its fields are laid out. Refusing at the declaration, not at the use, keeps every lookup unambiguous, which #225's rule (an error at the use) doesn't need to change.
8. **Reading and writing members.** A union's member is a place when its union is one, as a field is; reading one that wasn't last written gives its bytes reinterpreted (the program's business, as in C; no check, compiled or interpreted). Assignment, arguments and results copy a union whole, its `size` bytes.
9. **Literals** (`check_literal_values`, reached by `Value.{...}` and by untyped `.{...}` meeting a union through `check_convert`):
   - a union's literal gives at most one member, by name: `Value.{f = 1.5}`; the rest of its bytes are zero (the slot or the global is zeroed first, as a struct literal's). Values in order (`Value.{1.5}`) are `a union's literal names its one member, ...`; a second name is `a union's literal gives one member; 'i' is given already`. `Value.{}` is the union's zero value (Q4).
   - a name may reach through anonymous members (Q2): `Event.{kind = 2, key = k}`, as C's designated initializers do; the checker groups the values whose paths go through one anonymous member into a literal of its anonymous type it builds, at that member, recursively, so an anonymous union reached by two names (`Event.{key = a, mouse = b}`) is the union message at the second. In order, an anonymous member is one field taking a value of its type, usually an untyped `.{...}`: `Event.{2, .{key = k}}`.

10. **Constants and folding.** A union literal of constants is constant data, a constant's or a global's value, as a struct literal is. 11. **Comparison.** Nothing new: a union is a `TYPE_STRUCT`, which `takes_equality` refuses (`'==' needs ..., not 'Value'`), and which has no order.

## Not in this plan

- Passing unions, and structs, to and from C by value (Q1): #236, in milestone 6, with C's classification of a union's members per eightbyte on SysV and by size on Windows x64, byval/sret and coerced pieces in the IR, and the interpreter's thunk returning `rdx` and `xmm1`.
- Tagged unions, `union #tagged` (#224): `#tagged` after `union` is `expected '{', found directive` here.
- `using` (#225): it joins `type_find_member`'s walk (Decision 6).
- A named field of an anonymous type (`x: union { ... };`), an anonymous union or struct as a type anywhere else, and unions declared in a body.
- Comparing unions, overloading operators on them (#9 of the milestone), and checking which member was last written.
- `#if` among a union's members, and a union's member given a default value.

## Settled by the maintainer

- **Q1. A union by value to and from C:** (a), as structs today: through a pointer, by value refused by the existing messages. By value for structs and unions together is #236, in milestone 6 (Decision 12).
- **Q2. Naming fields reached through an anonymous member in a literal:** (a), allowed, as C's designated initializers allow (`Event.{kind = 2, key = k}`); an anonymous union still takes one member.
- **Q3. A `#run` result holding a union with a pointer member:** (a), baked as its bytes; an address from compile time in them is the program's business (Decision 13).
- **Q4. `Value.{}`:** (a), allowed, the union's zero value.
