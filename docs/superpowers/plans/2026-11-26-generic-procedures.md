# Generic Procedures Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Jai's generic procedures. `max :: (a: $T, b: T) -> T` declares `T` from its argument's type; `get :: (w: *World, $T: Type) -> *T` takes a type, `get(w, Position)`; `$N: int` takes a constant, so `[N]T` works in the body. One instance per distinct set of values, shared program-wide, each checked on its own, named `max(T = int)` in the debugger, the interpreter's frames and (mangled, `max$T$int`) the symbol table. An error inside an instance is followed by `in 'max' with T = Vec2, called at main.rig:12:5`, one line per instance up the chain. A generic body nothing instantiates has its names resolved but isn't type-checked. Types go where values go: a name that names a type, `*X`, `[N]T`, `[]T`, `[..]T` and `#type (int) -> int`; `T == int` is a constant `bool`, so `#if T == string` picks code per instance, and `size_of(T)`, `type_info(T)` and a `#run` inside an instance see that instance's `T`. Refused: a generic as a value (`'max' is generic; call it, or wrap one instance in a procedure`), `#foreign`, `#c_call` and `#compiler` generics, and `..` over types. `..$T`, default values and `#caller_location` work in generics. Compiled, interpreted and in a `#run`, on Windows and Linux; the debugger shows each instance.

**Architecture:**
- **Types as values** (Task 1): the parser reads `[`, which starts no expression today, and `#type` as a type in an `Ast_Type_Value`; a name or `*X` stays an `Ast_Name`/`Ast_Unary`. The checker never gives a type value to ordinary code: only the places that take one (`==`/`!=` with another type, a `$T: Type` argument; later #227's `Table(string, int)` and #228's `T = s64;`) call `check_type_value`, which types it `Type` (a new built-in type, `TYPE_TYPE`) and keeps the `Type *` it denotes. Everywhere else the existing `'Vec2' is a type, not a value` stands.
- **Instances are clones** (Tasks 2 and 4): the checker writes types and declarations into the tree, so each instance is a deep copy of the generic's unchecked `Ast_Proc` (`ast_clone`), with its bindings (`Ast_Alias` for a type parameter, `Ast_Const` for a constant one) in a lookup tier between the scopes and the top level (`Checker.instance`), and checked as any procedure is. The cache is the generic's own `Ast_Proc.instances` (the declaration is the program's one, so the cache is program-wide), compared binding by binding; `Ast_File.instances` lists every instance in creation order for check()'s last body pass and for lowering. A `$N`/`$T: Type` parameter is no parameter of its instance: its argument is dropped from the call.
- **Checking order:** an instance's signature is checked where the call needs it (`check_proc_signature`, so a decider does what it does for any signature); its body waits for check()'s pass over `Ast_File.instances`, after every other body and top-level `#run`, unless a `#run` reaches it first (`check_reached_body`). The generic itself gets a signature check of its own (`check_generic_signature`) and a name walk over its body (`check_generic_names`, Task 3), neither writing to its nodes.
- **Error context** (Task 3): `Diagnostics.context`, a string every error recorded while it's set takes into a new `Diagnostic.context`, printed after the caret and after a failed `#run`'s frames. `enter_instance` sets it from the instance's chain (`called_at`, `made_in`) wherever `Checker.instance` changes, so declarations worked out from inside an instance (set aside with the scopes) get none.
- **Lowering:** generic declarations are skipped; instances are procedures, keyed in `proc_index` by their symbol (`Ast_Instance.symbol`), with `Ir_Proc.name` the symbol and `source_name` the readable name, which the backend's subprogram and the interpreter's frames already use.

**Tech Stack:** C-style C++23, built with the pinned clang 23.1.5 (`build.bat`, `build.sh`), no STL; LLVM 23.1.5's C API; Rig for the tests; JavaScript (Node) for the VS Code extension's checks; gdb and cdb for the debugger tests.

**Spec:** GitHub issue #226 (`gh issue view 226 </dev/null`), whose Decisions are settled design; section 6 of the milestone's design, `docs/superpowers/specs/2026-11-22-milestone-5-type-system-design.md`, whose scope, non-goals (no variadic type parameters, no `Type` values at run time, no generic `#foreign`/`#c_call`/`#compiler`), anti-goals (an error in generic code names the instance and its call; nothing works compiled but not in `#run` or not in the debugger) and constraints bind every task; and `docs/rig-spec.md`, which each task updates for what it builds. Later issues build on the interfaces chosen here and are not implemented: #227 (generic structs, aliases), #228 (`#modify`), #229 (operators), #230 (Basic and Preload generic). Executors read all of these and this plan.

## Decisions this plan makes

1. **One PR, five tasks**, each green on both hosts, each a reviewer's gate:
   1. Types where a value goes, and the `Type` type.
   2. `$T` inferred from arguments: clones, the cache, instances checked and lowered, named, `T` inside them.
   3. Generic declarations checked on their own, uninstantiated bodies' names, and errors inside instances (the context chain, the depth limit).
   4. Explicit `$T: Type` and constant `$N` parameters, and the README line.
   5. `..$T`, defaults, `#caller_location` and `#run` in generics; the debugger tests.
2. **Syntax.**
   - `Param = [ "using" ] [ "$" ] identifier ":" [ ".." ] Type [ "=" Expression ]`; `Type` gains `"$" identifier`, allowed only inside a procedure declaration's parameter's type (any depth: `*$T`, `[]$T`, `[N]$T`, `[..]$T`, `($T) -> T`). Anywhere else (a result, a field, a variable, a cast, `size_of`, `type_info`, a literal's type, `#type`, a procedure type outside a parameter) the parser says `'$' declares a type parameter only in a procedure's parameter, as in max :: (a: $T, b: T) -> T`, at the `$`. Tracked by `Parser.in_param_type`, set around `parse_param`'s `parse_whole_type`.
   - `procedure_follows` and `parameters_follow` take `(` `$` too (Task 4). A procedure is generic (`Ast_Proc.is_generic`, set by the parser) when a parameter has a `$` before its name or a `$T` in its type.
   - Types in value positions (A.4's `Primary`): `"[" [ Expression | ".." ] "]" Type` (a type wherever an expression starts, since `[` starts none) and `"#type" Type` (any type; Jai's directive, needed for a procedure type, whose `(int)` reads as parentheses). Both make an `Ast_Type_Value`, at the `[` or the `#type`, its type a level below the expression (`parse_type_below`). A name and `*X` parse as today. No literal follows a type value (`[]int.{` stays "expected a field's name").
   - Dumps: `($N int)` and `($T Type)` for `$` parameters, `$T` for a declaring type name (`(items (view $T))`), `(type (view int))` for a type value.
3. **`Type`**: a built-in type, `type_type`, kind `TYPE_TYPE`, named `Type`, in `NAMED_TYPES` (so `Type :: struct {}` is the existing `'Type' is a built-in type`, and the editor colours it), size 8, alignment 8, never laid out at run time. `resolve_written` refuses it wherever a type is written: `'Type' only names types while compiling; a *Type_Info describes one at run time` (#228's wording, at the type). A `$T: Type` parameter is recognised by its written name before any type is resolved (Task 4), and so is the declaring `$T`.
4. **Type values** (`check_type_value`): an `Ast_Type_Value`, a name whose lookup finds a struct, an enum, an `Ast_Alias` (Task 2), or nothing while `type_from_name` knows it (so a local `int := 5;` hides the type `int`), and `*X` of one. Its `type` is `&type_type`, its `is_constant` stays false, and the `Type *` it denotes is kept in `Ast.constant`'s bits (`type_value(e)` reads it): never a run-time value, so nothing folds or lowers it by mistake. Places that take one: `==` and `!=` (when either operand names a type), and a `$T: Type` argument (Task 4). Everywhere else a type is refused as today: a name at the name (`'Vec2' is a type, not a value`, `*Vec2` at `Vec2`, the existing test unchanged), an `Ast_Type_Value` at its start with its type's name (`'[]int' is a type, not a value`).
5. **Comparing types:** `A == B` and `A != B` with both operands types are constant `bool`s (`is_constant`, `constant` 1 or 0: types are equal when their `Type *`s are), so they work in `#if`, in a constant's value and anywhere a `bool` goes; lowering sees only the constant. One type and one value: `'==' compares a type only with a type, as in T == int` (`'!='` for `!=`), at the operator. `<` and the others with a type operand say the operand's existing message.
6. **Representation of generics** (Interfaces, Task 2): `Ast_Type.declares` (`$T`), `Ast_Param.is_baked`/`dollar` (`$N`, `$T: Type`; Task 4), `Ast_Proc.is_generic`, `instances` (the cache), `instance` (an instance's record), `foreign_pos`; `Ast_Alias` (a name for a type: an instance's type parameter now, #227's `Name :: Type;` later); `Ast_Instance` (the generic, the clone, the bindings, the readable name, the symbol, the call that made it, the instance whose body made it, its depth); `Ast_File.instances`.
7. **The clone** (`ast_clone`, `ast.cpp`): a deep copy of a tree as the parser made it, for any node a procedure holds (its parameters, results, body, and every statement, expression and type in them; a top-level-only node is a `RIG_ASSERT`). Strings and positions are shared; every child node and every Array the parser filled are new (the checker appends to some); every field the checker fills is left zero (`type`, `is_constant`, `constant`, `to_any`, `decl`, `through`, `proc` of a call, `index`, `count_checked`, `resolve` states, `had_errors`, `Ast_Case.it`, `Ast_Jump.loop`, `Ast_Literal.fields`/`written`, `Ast_If_Directive.decided`/`taken`, ...). `Ast_Block.proc` points at the clone. The generic's own nodes are never written by any check (Decision 13), so every clone starts unchecked.
8. **Inference** (`check_generic.cpp`), for a call of generic `g`:
   1. Count the arguments against `g`'s parameters as `check_call` counts any (the same messages; `$` parameters count).
   2. Check each argument: a type value for a `$T: Type` parameter (Task 4), a value otherwise (`check_value`; a spread as today).
   3. Bind each type parameter from the arguments whose parameter's type names it, in parameter order, the first typed one fixing it: `match_type` walks the parameter's written type against the argument's type, binding an unbound name where it stands alone (`$T` or `T`), and looking through `*`, an array's, a view's and a resizable array's element (a `[]$T` pattern takes the element of an `[N]E`, `[]E` or `[..]E`: they convert to `[]E`), and a procedure type's parameters and results. A part that can't match (`[]$T` against `int`) is `argument 1 of 'first' has type 'int', which doesn't fit '[]$T'` (the parameter's type as written, `source_text`), at the argument. A name already bound isn't checked here: the argument's conversion (step 6) says any disagreement.
   4. A type parameter still unbound: if every argument at its positions is an untyped number, the untyped type they meet at (an untyped float if any is one, as `check_unify_numbers` does) gives its default type (`int`, `float32`); if one has no type of its own (`null`, `.{...}`, `.[...]`, `.FREE`), `can't work out 'T' for 'max': argument 1 has no type of its own`, at the first such argument; with no argument at all (a `..$T` given none, Task 5), `can't work out 'T' for 'max': no argument gives it`, at the callee.
   5. Find or make the instance (Decision 9).
   6. `call->proc` becomes the instance; `check_call` goes on exactly as for an ordinary call of it: each argument converts to its parameter's type with the existing messages (so `max(x_s32, y_int)` is `argument 2 of 'max' has type 'int', which can't be converted to 's32'`, Q3), defaults, context, `..` gathering.
9. **Instances** (`check_instance`): the cache is `g->instances`, compared binding by binding (a type by its `Type *`; a constant by its type and bits, a string by its bytes). Missing: `make_instance` clones `g` (Decision 7), drops the `$`-named parameters (Task 4), makes the bindings, names it, appends it to `g->instances` and `file->instances`, and checks its signature now (`check_proc_signature`), under `enter_instance`. The body waits (Architecture). A signature with errors keeps its instance (cached, `had_errors`): later calls with the same bindings get no type and say nothing more. The instance is made once whoever asks: a body, a global's value, a constant, a default value, a `#run`, a decider.
10. **Bindings and lookup.** `Checker.instance` is the instance whose signature, defaults or body is being checked: `resolve_signature` and `check_body` set it from `proc->instance` after `leave_scopes`, which sets it aside with the scopes (`Outer_Scopes.instance`), so a global, a constant or a type worked out from inside an instance doesn't see its `T`. `find_name` and `check_lookup` look in it after the scopes and the using parameters, before the top level (`instance_binding`). `check_body` also declares the bindings in the body's scope, so a local of a binding's name in the body's outer block is the existing "already declared" and an inner block may hide one, as for parameters. An `Ast_Alias` is a type wherever a type is written (`resolve_written`), a type value in `check_type_value`, the existing `'T' is a type, not a value` as a value, `'T' isn't a procedure, so it can't be called` as a callee, and `T.FREE`/`T.empty`/`T.{...}` when it aliases an enum, a tagged union or a struct (`check_member` takes the alias's type's declaration).
11. **Names and symbols.** `Ast_Instance.name` is `max(T = int)`: the generic's name, then `NAME = VALUE` per binding in the order the generic declares them, `, ` between. ## Not in this plan

- Generic structs, `Table(K, V)`, type aliases `Name :: Type;`, and `*Table($K, $V)` patterns (#227: `Ast_Alias`, `check_type_value` and `match_type` are where they go).
- `#modify` (#228: between `find_instance` and `make_instance`; `bindings_text` gives its `T = string`), and a variable of type `Type` there.
- Operator overloading and generic operators (#229: `check_instance` takes operands).
- Basic and Preload made generic (#230).
- `[$N]T`, inferring a constant from an array's count; `$` in a result; a type parameter with a default; variadic type parameters (a non-goal).
- `Type` values at run time (a non-goal): a type value converts to nothing, `Any` included.
- Showing a constant parameter (`N = 3`) as a constant in the debugger's view of an instance: the instance's name says it.
- Checking an uninstantiated body's types (Jai's rule, the issue's).

## Settled by the maintainer

- **A constant parameter `$N: X`** may have a number, `bool`, enum or `string` type. A string is compared by its bytes and named in quotes, `greet(S = "hi")`. Structs and arrays of constant data are refused.
- **A `$` parameter has no default value, for now:** `a parameter that declares '$N' can't have a default value, for now`. The same goes for `$T: Type` and for a parameter whose type declares `$T`.
- **Once `T` is fixed, every other argument at a `T` converts to it** as any argument does, with the existing conversion messages. `max(x_int, y_s32)` makes `max(T = int)`; `max(x_s32, y_int)` is `argument 2 of 'max' has type 'int', which can't be converted to 's32'`.
