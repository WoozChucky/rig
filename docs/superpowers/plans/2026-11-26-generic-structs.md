# Generic Structs and Type Aliases Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Jai's generic structs and type aliases. `Map :: struct (K: Type, V: Type) { ... }` and `Ring :: struct (T: Type, N: int) { items: [N]T; }` declare structs whose parameters every use gives; `Map(string, int)` names an instance wherever a type goes and wherever a value goes, instances with the same arguments being one type, program-wide; `Map(string, int).{...}` is a literal of one. Inside the struct `K`, `V`, `T` and `N` are types and constants, and a field may point at its own instance, `next: *List(T)`. A generic procedure takes any instance and binds its parameters from it, `(m: *Map($K, $V), key: K, value: V)`, a constant one too, `(r: Ring($T, $N))`. `Name :: TypeExpression;` declares an alias, the same type under a second name, at the top level and in bodies, a procedure type's written `Name :: (a: int) -> int;`. `Type_Info_Struct.name` is `Map(string, int)`, its new `parameters: []Any` holds the arguments, and the debugger names the instance the same way. An error inside an instance names it and where it was used, `in 'Ring' with T = int, N = -1, used at main.rig:5:8`. Compiled, interpreted and in a `#run`, on Windows and Linux.

**Architecture:**
- **Aliases** (Task 1): the parser keeps `Name :: e;` a constant (it can't tell `X :: Y;` apart); the checker, finding the constant's value names a type (`expr_names_type`), makes it an `Ast_Alias`, #226's node for a name of a type, kept in `Ast_Const.alias`, and every lookup that finds the constant returns the alias in its place, so every place that already handles an instance's `T` handles an alias. `Name :: Signature;` with no body and no `#foreign`/`#compiler` is a constant whose value is a procedure type (`Ast_Type_Value`).
- **Generic structs are clones too** (Task 2): a generic `Ast_Struct` has parameters and no `Type`; each distinct set of arguments makes an `Ast_Instance` (the record #226 made for procedures, given a struct half) holding a deep copy of the struct (`ast_clone`, extended to structs) named `Map(string, int)`, a fresh `TYPE_STRUCT` `Type` of that name, and its bindings (`Ast_Alias` per type parameter, `Ast_Const` per constant one). The copy is laid out as any struct, with `enter_instance` making its bindings visible between the scopes and the top level, exactly as for a procedure instance. The cache is the generic struct's `instances`; the instance is cached before it is laid out, so `*List(T)` inside `List(T)` finds it.
- **Written instances:** in a type, `Name(args)` is a new written-type kind, `AST_TYPE_INSTANCE`; in a value position it stays an `Ast_Call`, which the checker recognises by its callee (spec 5.20: a name is resolved after parsing). One function, `check_struct_instance`, binds both kinds of arguments.
- **Inference** (Task 5): `match_type` gains an `AST_TYPE_INSTANCE` case that reads an argument's struct instance's bindings; a `$N` written where the struct takes a constant declares a constant parameter of the procedure.
- **Type information** (Task 6): `Type_Info_Struct` gains `parameters: []Any`, appended; lowering writes it from the instance's bindings.

**Tech Stack:** C-style C++23, built with the pinned clang 23.1.5 (`build.bat`, `build.sh`), no STL; LLVM 23.1.5's C API; Rig for the tests; JavaScript (Node) for the VS Code extension's checks; gdb and cdb for the debugger tests.

**Spec:** GitHub issue #227 (`gh issue view 227 </dev/null`), whose Decisions are settled design; section 7 of the milestone's design, `docs/superpowers/specs/2026-11-22-milestone-5-type-system-design.md`, whose scope, non-goals (no constraints or traits, no variadic type parameters, no `Type` values at run time, no methods), anti-goals (an error in generic code names the instance and the use that made it; layouts C can read; nothing that works compiled but not in `#run` or the debugger; today's code keeps compiling) and constraints bind every task; `docs/rig-spec.md`, which each task updates for what it builds; and #226's plan, `docs/superpowers/plans/2026-11-26-generic-procedures.md`, whose interfaces this plan extends. Later issues build on what is chosen here and are not implemented: #228 (`#modify`, on a struct too: between `find_instance` and `make_struct_instance`), #229 (operators, `operator + :: (a: Vec($N), b: Vec(N)) -> Vec(N)`: Task 5's constant `$N`), #230 (Basic's `Table(K, V)` over typed `[..]` fields: Task 2's nested instances). ## Decisions this plan makes

1. **One PR, six tasks**, each green on both hosts, each a reviewer's gate:
   1. Type aliases.
   2. Generic structs, and their instances where types go.
   3. A generic struct's own check, and errors inside struct instances.
   4. Instances where values go, in literals, and aliased.
   5. Generic procedures over generic structs.
   6. Type information, `#run` and the debugger.
2. **Syntax.**
   - `StructDecl = identifier "::" "struct" [ "(" StructParam { "," StructParam } ")" ] "{" { FieldDecl } "}"`, `StructParam = identifier ":" Type`. Parsed by `parse_struct_params`, which refuses, each at the token named, giving the declaration up: `a struct's parameters take no '$': each instance gives them all, as in Map :: struct (K: Type, V: Type)` (`$`); `a struct's parameter can't be 'using'` (`using`); `a struct's parameter can't be '..'` (`..`); `a struct's parameter can't have a default value, for now` (`=`; as #226's Q2); `a struct with no parameters has no '()', as in Vec2 :: struct { x: float; }` (`(` of `()`). Per Q1, `union (` and `union #tagged (` are `a union can't take parameters, for now`, at the `(`. A struct with parameters is generic (`Ast_Struct.is_generic`).
   - `Type` gains `identifier "(" TypeArgument { "," TypeArgument } ")"`, an `AST_TYPE_INSTANCE` at the name. `parse_instance_argument` reads an argument as a written type when it starts as only a type can, `$` (in a parameter's type only, as today), `*` or `[`, or is a name, with or without its own `( ... )`, directly followed by `,` or `)`; any other argument is an expression (`parse_expression`): `4`, `N + 1`, `.B`, `Mode.B`, `"hi"`, `#type (int) -> int`, `#run f()`. A bare name is an `AST_TYPE_NAME` whichever it names; the checker reads one at a constant parameter as the constant it names (Decision 6). An instance's `(` is a level of the parser's limit (MAX_DEPTH), as a procedure type's `(` is (`parse_type` counts it at a name followed by `(`), so `Map(Map(...))` nested past the limit is `types are nested too deeply (more than 1000 levels)` rather than a stack overflow, and a field's `Ast_Type.levels` counts its instances' nesting (`inner: Wrap(Wrap(T));` is 2, which Task 3's `Wrap` test relies on).
   - In a value position `Map(string, int)` stays an `Ast_Call` (spec 5.20); the checker tells it apart (Decision 9).
   - Literals: `StructLiteral`'s and `ArrayLiteral`'s prefix becomes `[ identifier [ "(" Arguments ")" ] ]`: in `parse_postfix`, an `Ast_Call` whose callee is an `Ast_Name` not in parentheses, followed by `.{` or `.[`, becomes the literal's `AST_TYPE_INSTANCE`, its arguments the call's expressions as they are (the checker takes both shapes). `(Map)(K, V).{` and `a.Map(K, V).{` stay "expected a field's name".
   - Aliases: `Name :: Expression;` stays a `ConstDecl`. After `Name ::`, at the top level and in a body, a `(` begins a **procedure type alias** when `proc_type_alias_follows` holds: the `(` begins a signature (`procedure_follows`, or its `)` is followed by `->`), and after its `)`, outside parentheses, a `;` comes before any `{`, any directive but `#c_call` (`#foreign`, `#compiler`, `#no_abc`, `#caller_location`, a `#run` or `#load` starting the next line, ...) or the end of the file, as `variable_follows` reads a variable's procedure type; so `f :: () #caller_location;` and `f :: ()\n#run g();` stay `expected '{', found directive` (Fact 1's tests). It parses as a constant whose value is an `Ast_Type_Value` of `parse_proc_type` at the `(` (its names dropped, its `=` and `$` refused with `parse_proc_type`'s messages). `parse_local_declaration` asks before refusing a local procedure, and `starts_declaration` and `branch_declares_top_level` take a procedure type's alias as the constant it is, not a procedure's declaration, so a local one in column 1 doesn't end its body (`proc_type_alias_follows` takes where the `(` is, as `procedure_follows` does).
   - Dumps: `(struct Map (params (K Type) (V Type)) (keys (resizable K)))`; `(instance Map string (ptr u8))`, an expression argument as `dump` writes it, `(instance Ring int (binary + (int 4) (int 1)))` (a literal's arguments are a call's expressions, a name too: `(instance Pair (name string) (name int))`); `(literal (instance Pair (name string) (name int)) (string "a") (int 1))`; a procedure type alias `(const Cb (type (proc-type (params int) (returns int))))`.
3. **Aliases** (Task 1, spec 3.22).
   - A constant whose value names a type (`expr_names_type`: a type's name, `*X`, an `Ast_Type_Value`, and from Task 4 a written instance) is an alias: `check_const_value` checks the value with `check_type_value`, and makes `Ast_Const.alias`, an `Ast_Alias` at the constant's name, `aliased` the type; the constant's `type` is `&type_type`. An alias is the same type: `My_Int == int` is true, messages name the type as ever (`'Vec2' has no field 'z'` through `V :: Vec2;`).
   - `find_name` and `check_lookup` return `alias` in the constant's place; `find_name` first resolves a top-level constant it finds (`resolve_global`, as `check_lookup` does), so an alias is usable before its declaration, and a circle is the existing `'A' is defined in terms of itself` (`A :: B; B :: A;`, `S :: *S;`). A local alias is declared in order, as any local constant.
   - From there #226's handling of `AST_ALIAS` does the rest: a written type, a type value, `'V' is a type, not a value` (`check_named`), `'V' isn't a procedure, so it can't be called` (`check_callee`), `V.{...}`, `M.FREE` (`through_alias`).
   - Refused: an alias named as a built-in type, `'u8' is a built-in type`, at its name (top level or body: `resolve_written` looks there first, so it could never be named); `X :: Type;`, `'Type' only names types while compiling; a *Type_Info describes one at run time`. A value naming nothing stays a value: `Nope :: Missing;` is `unknown identifier 'Missing'`.
   - No code: lowering records no alias for a debugger (`is_shown_constant` false, `lower_statement`'s `AST_CONST` does nothing for one), `check_run.cpp`'s walk takes one as no code. An alias adds no debug type.
   - No generic aliases (none in the issue): `Pairs :: Pair(T, T);` outside an instance is `unknown identifier 'T'` (Task 4's argument check).
4. **Representation of generic structs** (Interfaces, Task 2). `Ast_Struct` gains `params`, `is_generic`, `instances`, `instance`, `had_errors`; `Ast_Type` gains `args`, `instance_type`, `instance_checked` (`AST_TYPE_INSTANCE`); `Ast_Instance` gains `generic_struct`, `structure`, `shown`; `Ast_File` gains `struct_instances`. A generic struct has no `Type` (`declared` stays null) and its own check uses its `resolve`.
5. **The generic struct's own check** (`check_generic_struct`, run in check()'s declarations pass in its turn, or earlier by its first use; Task 2 starts it, Task 3 completes it): each parameter `NAME: Type` is a type parameter; any other's type is resolved and must be a number's, a bool's, an enum's or `string` (`constant_parameter_type`), kept in the parameter's `Ast.type`, else `a struct's parameter is a type, 'T: Type', or a constant of a number, bool, enum or string type, not '[]int'`, at its type (Task 2). Task 3 adds, each said once at the generic, whether instantiated or not: two parameters of one name, and a field named as a parameter, `'K' is already declared at PATH:L:C` at the later; a parameter named as a built-in type, `'int' is a built-in type`; the fields' written types walked with `check_generic_type` (the parameters as types still to be known: `unknown type 'Nope'`, `'N' is not a type`, `'void' is only a pointer's target, as in *void`; array counts and instance arguments are each instance's); two fields of one name across its braces, `'a' is already declared at PATH:L:C`. A generic struct whose own check said anything makes no instance (`had_errors`): its uses have no type and say nothing more.
6. **Instances** (`check_struct_instance`, Task 2):
   1. Count: `'Map' takes 2 arguments, but 1 was given` (`1 argument` when one), at the instance's name.

## Not in this plan

- Generic unions and tagged unions (Q1).
- Reading a struct's parameter from outside it, `m.K`, `Map(string, int).V` (Q2).
- Default values for a struct's parameters (refused "for now", as #226's Q2 did for `$` parameters).
- Generic aliases, `Pairs(T) :: Pair(T, T);`, which the issue doesn't have.
- `#modify` on a struct (#228: between `find_instance` and `make_struct_instance`).
- Operators on instances (#229: Task 5's `Vec($N)` pattern is what a generic operator needs).
- Basic's `Table(K, V)`, `hash`, typed `sort` (#230).
- A debug typedef for an alias: an alias is the same type, with no name of its own in the program.

## Settled by the maintainer

- **Q1. Only structs take parameters, for now.** A union or a tagged union with parameters is refused: `a union can't take parameters, for now`, at the `(`.
- **Q2. A struct's parameters aren't read from outside, for now.** `m.K` gives the existing `'Map(string, int)' has no field 'K'`. A procedure gets the parameters by inference, `(m: *Map($K, $V))`.
- **Q3. `print` doesn't change.** An instance's name reaches a program through `type_info(...).name` (`Map(string, int)`), and an instance's value prints like any struct's.
