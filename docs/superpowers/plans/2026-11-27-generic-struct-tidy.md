# Tidy what generic structs left: plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Do what issue #246 asks, the polish left by generic structs and type aliases (#227, PR #245):
- a constant whose own declaration failed no longer gets a second `'X' is not a type` where it's used as a type;
- the VS Code grammar colours an alias of a named type, `V :: Vec2;`, as a type;
- gdb's `Box* u8` stays as documented, with the reason written down.

**Architecture:**
- **Checker.** Each `'X' is not a type` said of a constant `X` is recorded on the tree: the constant, and the message's index in the `Diagnostics`. At the end of `check()` it is withdrawn when `X` has no type and an error other than such a note was said inside `X`'s own declaration, from its name to its `;`. Deciding at the end, from positions, means the outcome never depends on declaration order. Saying the note at the use and withdrawing it later means nothing the checker does in between changes: `had_errors`, generic structs' refusals, error counts. A constant whose failure comes only from the use itself (a circle through a struct's field) has no error of its own, so its note stays.
- **Grammar.** A new declarations rule colours `NAME :: VALUE;` as a type alias, its value through `#type`, when VALUE is one of these:
  - a type for certain: a value starting with `*` or `[`, or a built-in type's name;
  - by a capitalisation heuristic (settled by the maintainer): a name that starts uppercase and has a lowercase letter, with or without an instance's arguments.
- **gdb.** No code change. A comment in `begin_debug_info` records the probe below.

**Tech Stack:** C-style C++23, no STL, pinned clang 23.1.5 (`build.bat`, `build.sh`); the VS Code extension's TextMate grammar (generated by `tests/unit/test_grammar.cpp`) and `editors/vscode/test/check.js` (plain Node).

**Spec:** issue #246 (`gh issue view 246`); `docs/rig-spec.md` 3.22 (the paragraph at :1665 ending "A constant whose value can't name a type ... is `'C' is not a type`") and 10.7 (:4823, already says what gdb shows; unchanged).

## Review Focus

1. **A silent circle keeps its message.** `S :: struct { a: C; } g: S; C :: g.a;`: C fails without a word, because `g.a` has no type, because of the field `a: C`. So the field's `'C' is not a type` is the program's only error. It must stay, in either order. A rule of "typeless means its mistake was said" would leave this program with no error at all. Task 1 Step 1 pins both orders.
2. **A note never counts as a constant's own mistake.** In `X :: cast(X) 1;`, the only message is the note itself, which sits inside X's declaration. It must stay. So must the notes that a constant's value says about another constant: in `X :: cast(Y) 1; Y :: 5;` both notes stay. Pinned in Step 1.
3. **Order independence.** The rule looks only at the final state: X's type and the messages' positions. A use before the declaration, in a struct's field, in a global's type, in a signature, or in a body behaves the same. So do a constant failing only through another constant (`X :: K + 1;`, kept in both orders) and a constant laid out by a top-level `#if`'s decider (the notes live on `Ast_File`, so `check()` sees the decider's). Pinned in Step 1 and in `tests/errors/failed_constant_as_type`.
4. **Withdrawing keeps the bookkeeping right.** `diag_withdraw` must decrement `error_count` as well as remove the message. The removals run from the highest index down, so each recorded index stays valid. Nothing may sort or clear `d->messages` between the note and the end of `check()`. That holds today: `compilation_print` runs only after `check()` returns. A `#run` that calls `exit()` mid-check prints through `diag_print_at_exit` before any withdrawal. That edge is accepted: it prints what was said so far.
5. **Grammar false positives.** `ADD :: add;`, `SAME :: SQUARES;`, `MINE :: OS;`, `R :: repeat(3);`, `A :: [2]int.[1, 2];`, `M :: Mode.A;` and `N :: (1 + 2);` must stay constants. The corpus check in `check.js` already fails if a name is coloured as a type that no struct, enum, `$T` or alias declares. It must keep passing on every program of `tests/run` and `tests/build`.

### Task 3: Say why the debug information stays C99 for gdb's names

- shipped in `.debug_gdb_scripts`, gdb would decline to load it under its default `auto-load safe-path` (`$debugdir:$datadir/auto-load`).

cdb reads CodeView, which has no DWARF language, and is unaffected either way.

## Settled by the maintainer

1. **How far the grammar guesses at an alias (Task 2):** the rule as written.
