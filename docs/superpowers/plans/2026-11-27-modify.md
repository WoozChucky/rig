# #modify Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Jai's `#modify`. A generic procedure or struct may carry a block of code that runs while compiling, once for each new set of bindings its uses ask for, before an instance is made: `sum :: (values: []$T) -> T #modify { return T != string, "sum needs numbers"; } { ... }`, `Box :: struct (T: Type) #modify { ... } { v: T; }`. Inside the block, `T` and the other parameters are variables, of type `Type` or of their constant's type. The block may assign them (`T = int;`), and the instance it makes is the one for the changed bindings, so `widen(cast(u8) 1)` and `widen(2)` can share `widen(T = int)`. It returns `bool`, or `bool, string`. `false` refuses the instance at the use: `'sum' refused T = string: sum needs numbers`. `type_info(T)` lets the block inspect the type. All of this works compiled, interpreted, in a `#run` and in the debugger, on Windows and Linux.

**Architecture:**
- **The block is a procedure of its own** (Task 1). The parser makes `#modify { ... }` an `Ast_Proc` named `#modify`, at the directive. It has no parameters, and its results are `bool` and `string`. The proc hangs off its generic through an `Ast_Modify`, which is not an `Ast`. The checker checks the block once, as the generic's own code, with no chain. The block's scope declares one `Ast_Var` per type or constant parameter: `T: Type`, `N: int`. Nothing in the block depends on what the bindings are, so one check serves every run. Inside it, a type written where a value goes is a value of type `Type`. `==` and `!=` on such values are worked out when the code runs, unless both sides are written types.
- **It runs in the compile-time world** (Task 2), as a `#run { }` does. Lowering makes it once per world, as `modify.N`. The IR proc takes the hidden pointer for its `string` result, then a pointer to a **bindings block**: one 16-byte slot per variable, in the generic's order. The block's variables live in those slots. `run.cpp`'s `compile_time_modify` writes the given bindings into the slots, runs the proc, reads its `bool` and `string`, and reads each slot back into a `Generic_Binding`.
- **Two caches.** A generic's instances stay keyed by their final bindings, as today. The `#modify` keeps its own cache, `Ast_Modify.runs`: the bindings each use gave, mapped to what the block did with them. A given set therefore runs once, and every given set that the block maps to the same bindings finds the same instance. `modify_bindings` sits between inference or argument binding and `find_instance`, in `check_instance` and in `check_struct_instance` (the hook #227 left).
- **How a `Type` value is held at run time** (Decision 6): it depends on whether the block inspects types. If the block takes `type_info` of a `Type` value (`Ast_Modify.describes`), each type is held as its description's address. The types the block is given are then described, and laid out, before each run. Otherwise each type is held as its `Type *`, an opaque handle, and nothing is described. Either way, `==` compares the handles.

**Tech Stack:** C-style C++23 built with the pinned clang 23.1.5 (`build.bat`, `build.sh`), no STL; LLVM 23.1.5's C API; Rig for the tests; Node for the VS Code extension's checks; gdb and cdb for the debugger tests.

**Spec:** GitHub issue #228 (`gh issue view 228 </dev/null`), whose Decisions are settled design except where Decisions 3 and 4 below reconcile them with what landed. Section 8 of the milestone's design, `docs/superpowers/specs/2026-11-22-milestone-5-type-system-design.md`, binds every task. Its scope, non-goals (no constraints or traits, `#modify` *is* the check; no `Type` values at run time), anti-goals (an error in generic code names the instance and the use that made it; nothing that works compiled but not in `#run` or the debugger; today's code keeps compiling) and constraints all apply. ## Decisions this plan makes

1. **One PR, four tasks**, each green on both hosts and each a reviewer's gate:
   1. Syntax, and the block's own check.
   2. Running it for generic procedures.
   3. Generic structs.
   4. The debugger, type information and `#run`.
2. **Syntax** (spec 7.12, 7.1, A.2, 2.7).
   - `ProcDecl = identifier "::" Signature ( { "#c_call" | "#no_abc" } [ "#modify" Block ] Block | ... )`.
   - `StructDecl = identifier "::" ( "struct" [ "(" StructParam { "," StructParam } ")" [ "#modify" Block ] ] | "union" ) "{" { FieldDecl } "}"`.
   - In `parse_procedure`'s loop, `#modify` reads a block (`parse_block`) as the body of a new `Ast_Proc` named `#modify`, at the directive. Its results are two written types the parser makes at the directive, `bool` and `string`. `modify_of` links back to the `Ast_Modify`. Then the loop ends, and the body's `{` must follow, so any directive after the block but a second `#modify` (below) is `expected '{', found directive`. A struct's `#modify` block is read the same way, after its `)`, before `parse_members`.
   - The parser refuses some forms and gives the declaration up each time:
     - `#modify` on a procedure that isn't generic (`!p->read_a_dollar`), after `struct` with no parameters, or after `union` or `union #tagged`: `#modify is for a generic procedure or struct, as in sum :: (values: []$T) -> T #modify { ... } { ... }`, at the `#modify`.
     - A second `#modify`: `'#modify' is written twice`.
     - Anywhere else, `#modify` gets the error for what was expected there (`expected an expression, found directive`, and so on), as `#type` does. It is added to `parse_procedure`'s list of directives that end the loop without being unknown.
   - Dumps add `(modify BLOCK)` after the directives and before the body: `(proc widen (params (v $T)) (returns T) (modify (block (return (bool true)))) (block (return (name v))))`. A struct's comes after its parameters: `(struct Box (params (T Type)) (modify (block (return (bool true)))) (v T))`.
3. **Reconciled with what landed.**
   - The issue's message for a `Type` variable outside `#modify` already exists (Fact 10). Nothing changes there.
   - Inside a block, the issue makes `Type` variables legal. A local's whole type may be `Type`, and it needs a value: `t: Type;` and `t: Type = ---;` are `a variable of type 'Type' needs a value, as in t := int;`, at its name.
   - `[]Type`, `*Type` and the like keep the existing message, in a block too.
   - The parameters a block sees are the generic's type and constant parameters, the `Generic_Binding`s `generic_parameters` and `struct_parameters` give, constant ones through an instance's argument (`Ring($T, $N)`) included.
   - The constant types are the landed ones: scalars and strings (settled).
   - A procedure's other parameters are not in the block's scope (`unknown identifier 'values'`, or the top-level name they would otherwise find): no call's arguments exist when it runs.
4. **"Once per new instance"** reads as: once per new set of bindings given. The issue says the block runs once per new instance, but a block that maps `u8` to `int` makes no new instance for `u8`, and must still run for it. So it runs once for each set it is given, whatever instance that set ends at (Review Focus 1). Its result is final: it is never run again on its own result.
5. **The block's own check** (`check_modify`, Task 1, spec 7.12): once, as the generic's own code, with no chain, whether an instance is ever asked for or not. It is checked the first time an instance is asked for, or else in `check()`'s bodies pass. A generic struct's is checked there too, after its own check.
   - Its variables are made and declared in its scope, so a local can't take `T`'s name there.
   - Its body is checked with `check_reached_body`, scopes left. `Checker.modify` is set while it's checked, and a procedure it calls is checked with it null.
   - Then its reach is walked, as a block `#run`'s is (`reach_modify`), so a body it reaches has no errors before any run.
   - A mistake in any of this is the generic's: `Ast_Modify.had_errors` and the generic's `had_errors` are both set, and the generic makes no instance. Its uses say nothing more.
   - In a block (`c->modify` set):
     - A written type where a value goes (`expr_names_type`) is a value of type `Type` wherever a value goes (`check_value` gives it to `check_type_value`): `T = s64;`, `t := int;`, `T != Pair(int, int)`.
     - `==` and `!=` with two operands of type `Type`, variables or written types, compare types. The result is constant (as today) only when both operands are written types. Otherwise `operand_type` is `Type`, and the comparison is worked out when the block runs. So `#if T == int` in a block is the existing `the condition of '#if' must be known while compiling`, and `if` is what a block uses.
     - `type_info(t)`, with `t` naming a variable of type `Type`, is that variable's description, read when the block runs (`Ast_Type_Info.of`). It sets `describes`.
     - A written type that names such a variable (`x: T;`, `size_of(T)`, `[]T`) is `'T' is a variable of type 'Type', not a type; type_info(T) describes it, as in type_info(T).size`, at the name.
     - `*T` of a `Type` value is `can't take the address of 'T': it's a 'Type'`.
     - A `Type` value converted to `Any` (`print("{}", T)`) is `a value of type 'Type' can't be an 'Any'; type_info(T) describes the type`, at the value.
     - Any other use of a `Type` value gets the existing conversion and operator messages (`T + 1`, `f(T)` for an `int` parameter, `T = 5`).
     - `return b;` gives an empty message: `check_return` appends an `Ast_String` "" at the return, so lowering sees two values.
     - Any other count of values is `a #modify block returns a bool, and may add a message, as in return T != string, "sum needs numbers";`, at the `return`.
     - Reaching the end is `'#modify' must return a bool on every path, and this one reaches its end`, at the `}`.
     - `Checker.modify` is set for the block's own body only, so outside a block nothing changes.
6. **A `Type` value when the block runs** (Tasks 1 and 2; see the Architecture section and Q1). `ir_type_of(Type)` is `IR_PTR`. A read of a `Type` variable is a load of its slot.
   - If `describes` holds, a written type in the block lowers to its description's address (`type_info_global`). `run.cpp` describes each given type binding first: the walk `reach_descriptions` lays it out, `ir_lowering_type_info` lowers its description, and `interp_map` maps it, so that `interp_global` gives the address it writes. Reading back, `interp_global_at` and `ir_lowering_described` turn the address into the `Type *`.
   - Otherwise a written type lowers to `inttoptr (i64 Type *)`. `run.cpp` writes and reads the `Type *` itself, and nothing is described or laid out for the run.
   - A comparison of types at run time compares the two pointers. A type never has two handles, since types are interned (Fact 7).
   - The walk (`walk_expression`) takes a constant comparison of types as a leaf, its operands never looked at (today the comparison, of type `bool`, is walked, and its operands are leaves for their type `Type`, 226). It takes any other node of type `Type` as either a variable's read (nothing more) or a written type, whose description it reaches only when `describes`. Only a block's code has such nodes.
7. **The run** (Task 2, spec 7.12, 7.8, 10.8). `compile_time_modify`:
   - Makes the world's parts if needed, and lowers the proc once (`ir_lower_modify`: `modify.N`, `source_name` `#modify`, IR params `ptr` (the hidden `string` result) and `ptr` (the bindings block), result `i1`, with the default context as a run's).
   - Fills a zeroed block of `MODIFY_SLOT_SIZE` (16) bytes per variable. A type is written as in Decision 6. A constant is written as its value lies in memory: its canonical bits, `t->size` of them. A string is written as its count and data, its bytes copied first into the run's scratch memory, so the block can't write into the program's literal.
   - Runs it. A failure is `#modify failed: runtime error: MESSAGE`, at the `#modify`, followed by its frames, the outermost `    in #modify (PATH:L:C)`; `report_failure` takes the word.
   - Reads back the `bool` (`results[0]`), the message, baked as a string with `bake_value` (copied into the checker's arena), and each slot: a type as in Decision 6, a constant with `bake_value` into the binding's `value`. A string with a negative count is refused by baking, with the word `#modify` (`#modify failed: its result holds a string with a negative count`).
   - The block shares the compile-time world with every `#run`: what it leaves in globals, later runs see. Its time counts as the runs' time. Nothing of it reaches the program's module.
8. **Which instance a use makes** (`modify_bindings`, Task 2):
   1. While a top-level `#if` is decided (`c->deciding`): `a top-level #if's condition can't run code while compiling, for now`, at the use. First, so the block is never checked by a decider, which knows only what's outside every top-level `#if` (`check_modify` doesn't check it while deciding, since Task 1).
   2. The block's check (Decision 5). If it is under way, the use comes from the block itself, or from code the block reaches, asking for its own generic's instance: `'sum' can't be used in its own #modify, which decides its instances`, at the use, said by `check_modify` since Task 1. The check then has an error, and the generic makes no instance.
   3. The cache: `Modify_Run` in `modify->runs` whose `given` matches the bindings (`same_binding`, as `find_instance` compares). If there is none, the given bindings are made (`make_bindings`) and the block runs. While it runs, `Diagnostics.context` is the would-be instance's line, `    in 'sum' with T = string, called at PATH:L:C` (`used at` for a struct), over the caller's chain, so a failure is followed by it.
   4. Failed (a walk's error or a run's failure, said once, then): false, and nothing more is said at this use or at any later use with these bindings.
   5. Refused: `'sum' refused T = string: sum needs numbers`, or `'sum' refused T = string` for an empty message, at the use, with the caller's chain. It is said at every use that asks for those bindings (Q3). The bindings are the given ones, as `bindings_text` writes them.
   6. Accepted: the bindings become the block's result. Then `find_instance`, else `make_instance` or `make_struct_instance`, exactly as today. The instance is named and chained by its final bindings (`widen(T = int)`, `in 'widen' with T = int, called at ...`), `called_at` and `made_in` being those of the use that made it.
   - The cache is the generic's, program-wide. A use in another file, in a `#run`, in an instance's body or fields, through an alias, `B :: Box(u8);`, or as a literal's type, `Box(u8).{1}`, runs nothing new for bindings already given.
9. **After the block, a call is any call** (Task 2, spec 7.12, 7.11). Its arguments convert to the parameters of the instance the final bindings make. So a `widen(cast(u8) 3)` mapped to `T = int` passes a `u8` that widens, while `sum(u8_view)` mapped to `T = int` is `argument 1 of 'sum' has type '[]u8', which can't be converted to '[]int'`. A changed `$N` is the instance's constant (`ring(0, int)` with `N = 1` returns a `[1]int`). Inference through an instance, `(b: Box($T))`, reads its final bindings.
10. **Generic structs** (Task 3, spec 3.23, 7.12). `check_struct_instance` calls `modify_bindings` after binding the arguments, at the instance's name. So `Box(u8)` and `Box(int)` are one type, named `Box(int)` by its final bindings, wherever written, and `Type_Info_Struct.name` and `parameters` say so. ## Not in this plan

- `cast(Type)` of a `*Type_Info`, which would set a parameter from what `type_info` shows, such as the type a pointer points at (Q2).
- `Type` anywhere in a block but as a variable's whole type: no `[]Type`, `*Type`, `Type` parameters or results.
- `$` defaults, and parameters on unions (settled: not for now).
- Reading a struct's parameters from outside it, `m.K` (settled: not for now).
- `#modify` in Basic and Preload (#230: `hash` refusing other types, `sqrt` restricted to floats).
- Operators (#229): a generic operator with a `#modify` is #229's to decide.

## Settled by the maintainer

- A constant parameter is a scalar or a string (#226, #227).
- No default values for `$` parameters, for now (#226's Q2).
- Only structs take parameters, for now (#227's Q1).
- A struct's parameters aren't read from outside it, for now: `m.K` is `'Map(string, int)' has no field 'K'` (#227's Q2).
- **Q1.** A block holds a type as an opaque handle. A type is described, and so laid out, only when the block calls `type_info` on it. `Node :: struct { w: Wrap(Node); next: *Box(Node); }` still compiles when the blocks only compare.
- **Q2.** No `cast(Type)` from a `*Type_Info` for now. A block sets a parameter only to a written type or another `Type` value.
- **Q3.** A refusal is said at every use that asks for those bindings. The block still runs once per set of given bindings.
