# Features

What works today, as [the specification](/spec/) describes it. The specification is the full account; this page is the tour.

- **Numbers and bools:** integers of every width (`s8` to `s64`, `u8` to `u64`, `int`) with arithmetic, bitwise operators and shifts, which wrap; `float32` and `float64` (`float` is `float32`), IEEE 754's; `bool`, with comparisons, `&&`, `||` and `!`. Casts are checked: `cast(u8) x` stops the program if the number would change, `cast,trunc(u8) x` keeps the low bits, and a float cast to an integer truncates and saturates.
- **Data:** pointers (`*int`, `*x`, `p.*`, `null`, pointer arithmetic, `*void`, `size_of(T)`), structs laid out as C lays them out (`Vec2.{1, 2}`), C's unions (`Value :: union { i: s64; f: float64; }`, every member at offset 0, `Value.{f = 1.5}`) and anonymous `union { ... };` and `struct { ... };` members, whose fields are reached directly (`e.key`), `using` fields (`Player :: struct { using entity: Entity; health: int; }`), whose struct's fields the struct reaches as its own (`p.position`), through a pointer too (`using transform: *Transform;`), a value one letting a `*Player` convert to a `*Entity`, tagged unions, which know which member they hold (`Shape :: union #tagged { circle: Circle; empty: void; }`, `Shape.{circle = c}` or `.empty`; read in a switch with a case for every member or a `case;`, `if s == { case .circle; ... }`, where `it` is the member; tested with `s == .empty`), enums over an integer type (`Mode :: enum { ALLOCATE; FREE; }`, their members `Mode.FREE`, or `.FREE` where the type is known) and sets of flags (`enum_flags`, with `| & ^ ~`), type aliases, the same type under a second name (`Ints :: []int;`, `Cb :: (n: int) -> int;`), fixed arrays (`[3]int`, `int.[1, 2, 3]`), views (`[]int`, a count and a pointer), resizable arrays (`[..]int`, which converts to a view of its elements and grows from its own `.allocator`, the context's allocator, taken when it first grows, unless it was given another, with the built-in `array_add`, `array_insert`, `array_pop`, `array_remove_ordered`, `array_remove_unordered`, `array_reserve`, `array_resize`, `array_reset` and `array_free`) and strings (a view of bytes: `s.count`, `s[0]`, `==`), gone over with `for a` or, to change them, `for * a`.
- **Procedures** that return several results (`q, r := divmod(7, 2);`), parameters with default values (`times: int = 2`), which a call may leave out, `#caller_location` among them, the place of each call that leaves its parameter out (`loc: Source_Code_Location = #caller_location`), variadic procedures (`args: ..Any`), whose parameters after the `..` one take their default values, `using` parameters, whose struct's fields the body names directly (`move :: (using e: *Entity, dx: float) { position.x += dx; }`), and procedure values: types such as `(int, int) -> int`, procedures kept in variables, fields and arrays and called through them, and `#c_call` procedures that C can call back; generic procedures, `max :: (a: $T, b: T) -> T`, whose `$T` each call works out from its arguments (`max(1, 2)`, `first(names)` with `first :: (items: []$T) -> T`), compiled once for each set of types and shared by every call that needs it, with `T` a type in the body (`#if T == string`, `size_of(T)`), and types and constants given as parameters, `get :: (w: *World, $T: Type) -> *T` called `get(w, Position)`, `ring :: ($N: int, $T: Type) -> [N]T` whose `N` sizes an array, `..$T` (`sum :: (values: ..$T) -> T`), default values and `#run`s each instance has of its own, and instances a debugger names `max(T = int)`; types written where values go and compared while compiling (`int == s64` is false, `[]int != [..]int`, `#type (int) -> int == #type (int) -> int`), constants an `#if` decides on; the context, which every procedure but `main` and a `#c_call` one is given without naming it, so code deep in a call chain takes its memory from `context.allocator` or the temporary storage, an allocator reads the place it is asked from in `context.allocation_location`, and `push_context` runs a block with another context; variables, constants and globals, with top-level declarations in any order; `if`, the switch, `if x == { case 1; ... }`, with `#through` and `#complete`, `while`, and `for` over a range or a sequence with `it` and `it_index`, `break` and `continue`, and `defer`, which runs a statement when its block is left, however it is left.
- **Programs of several files:** `#load "world/map.rig";` makes another file part of the program, its declarations joining the program's one top level. Each file is loaded once, so files may load each other.
- **Code run while compiling:** `#run` runs the program's own code on the compiler's interpreter while it compiles. `PRIMES :: #run primes();` bakes what `primes` returns into the program as a constant, an array's count may be a `#run`, and a top-level `#run { ... }` runs for its effect.
- **Conditional compilation:** `#if OS == .WINDOWS { ... } else { ... }` is decided while compiling, and only the branch it takes is part of the program, at the top level or in a body. The predeclared constant `OS`, of the predeclared enum `Operating_System` (`.WINDOWS` or `.LINUX`), says which system the program is built for.
- **Modules:** `#import "Basic";` makes a module that ships with rig part of the program. Every program imports Preload without asking: it holds what the language itself refers to, for now the `Allocator`, its modes, an enum, `Allocator_Mode`, and the heap allocator, type information, an enum's members' names and values among it, and `Any`, the context, its default and the temporary storage with its allocator, the resizable arrays' layout, `Resizable_Array`, with the procedures, written in Rig, that grow and shrink them, `Source_Code_Location`, the place a `#caller_location` is, and the command-line arguments, saved before `main` runs. Basic is Rig's first library, written in Rig: text and numbers, math (min, max, clamp and abs, π and C's math functions), allocators and the context's temporary storage, a string builder, hash tables, sorting and searching, paths, files and directories, the clock, the calendar and sleeping, random numbers, the environment's variables, commands and their output (files, directories, variables and commands all in UTF-8, on Windows too), the command-line arguments, formatted printing, which writes an enum by its members' names, standard error and `assert`, and a memory debugger, an allocator that wraps another and reports what a program never freed, and what it freed twice, each at its line. Compiler is what build programs use.
- **Build programs:** a `build.rig`, written in Rig in place of a build script, that imports the Compiler module and has no `main`. Its `#run`s make workspaces, each a program to build with its own options (its output's name, optimised with LLVM's O2 pipeline or not, bounds checks on or off), and `rig build` with no file runs it and builds them ([the README](https://github.com/WoozChucky/rig#building-with-buildrig)).
- **Runtime checks, on by default:** an index out of bounds, a null pointer dereference, an integer division by zero or a checked cast that would change a number stops the program with `PATH:LINE:COL: runtime error: MESSAGE` and exit status 101, and so does a failed `assert`. `#no_abc` or `--no-bounds-checks` turns the bounds checks off.
- **C interop:** a C function declared once with `#foreign libc` is called like any procedure, with the platform's C calling convention.
- **Diagnostics** that name the file, line and column and show the line.
- **Debug information** in every build: a PDB on Windows, DWARF on Linux. gdb, cdb, WinDbg, Visual Studio and VS Code stop at a line of any of the program's `.rig` files or at a procedure by its Rig name, show the call stack, step a line at a time, and show the variables and the named constants with their values, in an unoptimised build.
- **Windows x64 and Linux x86-64**, linked by the linker and runtime that ship with Rig against the system's C runtime, `ucrtbase.dll` and `kernel32.dll` on Windows, glibc's `libc.so.6` and `libm.so.6` on Linux, with nothing else to install.

Where each milestone stands is on [the roadmap](https://github.com/WoozChucky/rig/issues/85).
